## 1. 项目概述

### 通俗版

Mortal 是一个**日本麻将 AI**。它不与人对弈来学习，而是**"看"大量人类高手的牌谱录像来学习**——就像一个学生反复观摩职业棋手的比赛录像，从中总结"在什么局面下该打什么牌"。

本项目在开源 Mortal 的基础上进行了一系列训练方法实验，核心探索方向是：**当模仿学习到了极限之后，如何让 AI 学得比人类更强？** 这条路线最重要的实验是把"离线强化学习"（IQL，Implicit Q-Learning）引入麻将决策训练——**已判定无统计增益并关闭（2026-10-16）**；此后主线转移为**数据侧扩窗（2019+ 并重训 GRP）+ 信息侧读牌后验注入（S6：给模型人类看不到的对手暗牌/听牌信息）**。

### 严格版

项目目标是从固定的**离线数据集** \(\mathcal{D}\)（人类高手对局的 mjai 格式牌谱）中学习一个策略 \(\pi(a\mid s)\)，使 AI 的实际对局强度（以配对对抗的期望点差衡量）超过训练数据所代表的人类水平。学习范式经历了三个阶段：

1. **行为克隆 + MC 回归**（cql_mc 路径）：直接回归"人类在该局面下的实际选择所对应的回报"；
2. **跨局信用分配**（Stage A，`credit_mode='game'`）：把整场回报沿折扣后缀和回传给更早的局——已实测否决；
3. **离线价值学习**（Stage B，`objective='iql'`）：引入 Bellman bootstrap、状态价值网络与优势加权策略提取——**2026-10-16 判定：τ=0.5 干净条件下 δ=+0.646（bootstrap 95%CI[−0.35,+1.63]）无统计增益，路线关闭**。当前主线：数据侧扩窗（2019+，重训 GRP）；信息侧读牌模型后验注入（S6b，另 S6a 紧迫度特征已判 +0.182 无结论、归因为零新信息）。

## 2. 背景知识速成

### 2.1 日本麻将与天凤

日本麻将（立直麻将）是四人游戏：每家 13 张手牌，通过摸牌、打牌、吃/碰/杠和牌。一场对局（半庄）由若干**局**（kyoku）组成，每局结束按顺位结算**点数变动**，最终按总点数排 1–4 位。本项目使用**天凤**（Tenhou）平台的**凤凰卓**（凤凰桌，天凤最高段位桌）对局记录作为数据。

### 2.2 mjai 牌谱格式

mjai 是一种事件流格式的牌谱：一局牌被记录为 `{"type":"tsumo",...}`、`{"type":"dahai",...}`（打牌）、`{"type":"reach",...}`（立直）等事件序列。它**只包含客观发生的事件**，不含任何 AI 中间状态——所有训练用的特征都要从事件流重放重建。

### 2.3 离线强化学习（Offline RL）一句话

普通强化学习让 AI 自己下场玩、从输赢中学习；**离线**强化学习则只给定一份固定不变的"录像集"，AI 只能从录像里学，不能自己尝试。这带来一个核心难题：**录像里人类没做过的选择，AI 不知道其好坏**（分布偏移问题）。IQL 就是为解决这个难题设计的算法之一。

### 2.4 强化学习基本符号

| 符号 | 含义 | 本项目中的对应 |
|---|---|---|
| \(s \in \mathcal{S}\) | 状态 | 某决策时刻的完整可观测局面（编码为 128 通道特征平面） |
| \(a \in \mathcal{A}\) | 动作 | 46 维动作空间中的一个（见 §4.3） |
| \(r\) | 奖励 | 每局结束时的期望点差（见 §6） |
| \(\gamma\) | 折扣因子 | 0.997（iql 模式） |
| \(\pi(a\mid s)\) | 策略 | "看到局面 \(s\) 时选动作 \(a\)" 的规则 |
| \(\pi_\beta\) | 行为策略 | 产生数据的人类高手们的策略 |
| \(Q(s,a)\) | 动作价值 | "在 \(s\) 做 \(a\) 之后按某策略走下去，预期能拿到多少回报" |
| \(V(s)\) | 状态价值 | "在 \(s\) 处按某策略走下去的总体预期回报" |

## 4. 数据管线：从牌谱到训练样本

### 4.1 通俗版：什么是"决策点"

想象慢放一盘人类的牌局。每当轮到**你**做选择的那一瞬间，就是一个**决策点**：刚摸完牌该打哪张？别人打出的牌要不要碰？要不要立直？

数据管线的工作就是：重放牌谱 → 在**每一个**决策点停下来，记录三样东西——

1. **你当时看到的局面**（特征平面 obs）；
2. **你当时可以选什么**（合法动作掩码 mask）；
3. **你实际做了什么**（动作 label）。

### 4.2 严格版：加载与编码

牌谱引擎（[libriichi/src/dataset/gameplay.rs](libriichi/src/dataset/gameplay.rs)）对每个座位独立重放事件流。用 4 事件滑动窗口匹配"决策—结果"对：窗口中 `cur` 是触发决策的事件（如摸牌），`next` 是结果事件（如打牌 X），由 `next` 反推 label；仅当状态机给出 `cans.can_act()` 时才生成样本条目。

每个条目包含：

| 字段 | 说明 |
|---|---|
| `obs` | 玩家视角特征平面（version 4：128 通道 × 34 列） |
| `actions[i]` | label ∈ [0, 46) |
| `masks[i]` | 合法动作布尔掩码 |
| `at_kyoku[i]` | 该决策点属于第几局 |
| `dones[i]` | 是否局边界（下一条目进入新局） |
| `apply_gamma[i]` | 该动作是否"消耗一个巡目"（参与折扣计数，判据 `label ≤ 37`） |

**视角增强**：同一局牌会为 4 个座位各生成一套数据（4 个视角），还可加"换位/换局序"增广（augmentation），这使有效样本量 ×4 以上。

### 4.3 动作空间（46 维）

| label | 含义 | label | 含义 |
|---|---|---|---|
| 0–36 | 打牌（每张牌一个） | 41 | 碰 |
| 37 | 立直宣告 | 42 | 杠（大明杠/加杠/暗杠） |
| 38–40 | 吃（低/中/高） | 43 | 和了 |
| — | — | 44 | 九种九牌流局 |
| — | — | 45 | 主动 pass（不鸣牌/不和） |

细节：立直后必打的那张牌在**立直宣告决策点**已隐含确定，不产生额外决策点；多候选杠时额外生成一个"杠选牌"决策点（`at_kan_select=True`，label 为牌 id 0–36）。

## 5. 模型结构

### 5.1 通俗版

模型像一个"读牌大师"：先看完整牌面信息，在脑中形成对局面的**综合理解**（一个 1024 维向量），再从这个理解出发回答不同的问题——"每个动作打多少分？"（Q 头）、"现在局面胜算如何？"（V 头 / GRP）。

### 5.2 严格版（[mortal/model.py](mortal/model.py)）

**编码器 Brain**（`conv_channels=192, num_blocks=40`）：

\[
\phi_\theta(s) \in \mathbb{R}^{1024}
\]

- 输入：\(\mathbb{R}^{128 \times 34}\) 特征平面；
- 40 个预激活 **1D ResNet 块**（每块两层 \(3\times1\) 卷积 + BN + Mish 激活），每块带**通道注意力**（SE 风格：全局平均+最大池化 → 两层 MLP → sigmoid 门控）；
- 尾部：卷积降到 32 通道 → Flatten → 线性层得 1024 维隐向量。

**Dueling DQN 头**（version 4，一个线性层拆出 V 与 A）：

\[
Q_\theta(s,a) = V(s) + A(s,a) - \frac{1}{|\mathcal{A}_{\text{legal}}(s)|}\sum_{a'\in\mathcal{A}_{\text{legal}}(s)} A(s,a')
\]

其中非法动作被填 \(-\infty\)。**通俗地说**：Q 值 = "这个局面本身值多少"（V）+ "这个动作相对平均好在哪"（A）。 duel 结构让网络可以"先评估局面、再比较动作"，学起来更稳。策略 \(\pi_\theta\) 直接取 Q 的 softmax（AWR 阶段）或 argmax（对局阶段）。

**VHead**（Stage B 新增）：\(V_\eta(s)\)，结构 Linear(1024→256)→Mish→Linear(256→1)。（IQL 路线关闭后该头仅随 `objective='iql'` 存档保留，主链 cql_mc 不实例化。）

**GRP（Game Rank Predictor，`GRP` 类见 [mortal/model.py](mortal/model.py)，训练脚本 [mortal/train_grp.py](mortal/train_grp.py)）**：GRU 循环网络（全程 float64；当前正式轮 hidden_size=128、num_layers=3）。输入是**按局的前缀序列**（每个训练样本取 `feature[:i+1]`，即"已看到前 i+1 个局的开局形势"），每步一个 7 维向量（`GRP_SIZE=7`，[libriichi/src/consts.rs](libriichi/src/consts.rs)，由 [libriichi/src/dataset/grp.rs](libriichi/src/dataset/grp.rs) 从 `StartKyoku` 事件构造）：

\[
x_k = \big[\,g,\ h,\ t,\ s_0/10^4,\ s_1/10^4,\ s_2/10^4,\ s_3/10^4\,\big]
\]

依次为：全局局号 \(g\)（E1=0…E4=3，S1=4…S4=7，W1=8…W4=11）、本场数 \(h\)、供托（立直棒数）\(t\)、四家在该局**开局时**的点数（万点单位，E1 恒为 2.5；\(s_0\) 为 player id 0 的分数，绝对座位口径）。输入**不含任何手牌、牌河、副露信息**，纯粹是分数形势。GRU 取最终隐状态过 MLP，输出 `(N, 24)` logits：24 = 4!，即"四家最终顺位"的全部排列（第 \(j\) 个输出对应 `permutations(range(4))` 的第 \(j\) 个排列 \(p\)，含义为 player \(i\) 终局排第 \(p[i]\) 位），softmax 后与真实排列索引（`get_label` 由终局 `rank_by_player` 生成）做交叉熵；`calc_matrix` 再把 24 维概率边际化为 `(N, 4玩家 × 4顺位)` 的矩阵（`matrix[:, player, rank] = P(player 排第 rank)`）。**通俗地说**：根据半庄开局至今的分数形势，预测打到终场各家大概排第几。它在训练中充当"裁判"：顺位概率矩阵经 `RewardCalculator`（[mortal/reward_calculator.py](mortal/reward_calculator.py)）与 `pts` 求期望并逐局差分，得到每局的期望点差奖励（见 §6）。

**辅助头 AuxNet**：从 \(\phi\) 预测下一局自己的顺位（aux loss，权重 0.2），迫使编码器保留"局间连续性"信息。

## 6. 奖励设计与 gamma 的语义

### 6.1 通俗版：怎么给一局牌"打分"

AI 每打完一局，按**最终顺位**得分：本项目 B 口径为 `pts = [2, 1, 0, -3]`（第 1 位 +2 分……第 4 位 −3 分）。但训练时不能用"事后才知的顺位"直接打分——训练进行到一半时终局还没发生。于是用 **GRP**（§5.2 的顺位预测器）在每个局开始时给出顺位概率预测，算出**期望点差**：

> 这局按目前形势打下去，你预期能挣多少分？

这个"GRP 期望点差"就是每局的奖励 \(R_k\)。

### 6.2 gamma 的语义：三种模式对比（实测核对结论）

**⚠ 这里是本项目最容易误解的地方**，以下为 2026-10-12/10-16 两轮实测（合计 >11 万动作样本）验证过的代码事实（验证工具：[tools/training/inspect_gamma_semantics.py](tools/training/inspect_gamma_semantics.py)）。

**模式一（基线，`credit_mode='kyoku'` + `objective='cql_mc'`）**：

样本 \(i\) 的训练目标是

\[
y_i = \gamma^{\,n_i} \cdot R_{k(i)}, \qquad n_i = \sum_{j=i}^{e_k-1} \mathbb{1}[\text{apply\_gamma}_j]
\]

其中 \(k(i)\) 是样本 \(i\) 所在的局，\(e_k\) 是该局最后一个条目。三个实测确认的事实：

1. **折扣判据**：`apply_gamma = (label ≤ 37)`，即打牌(0–36)与立直(37)参与折扣计数；鸣牌/杠(42)/和了/pass 都**不**参与（源码 [gameplay.rs#L434](libriichi/src/dataset/gameplay.rs#L434)；注意旧注释 "only discard and kan" 与实现不符，已修正）。
2. **折扣视界 = 当前局内**：计数 \(n_i\) 在局边界**归零重启**（`dones` 截断累加），局末那条动作永远拿满 \(\gamma^0=1\)。
3. **奖励只取本局**：\(R_{k(i)}\) 是**当前局**的奖励，后续局的收益完全不进入样本 \(i\) 的目标。

> **通俗地说**：在这个模式下，\(\gamma<1\) **不是**"跨局信用分配"——它只是把同一局里较早的动作稍微降一点权重（一场 \(\gamma=0.995\) 时每动作约打 99.5 折，一局十几个决策点合计约 95 折）。"AI 看不到这局的结果会怎样影响前面的决策"这个跨局问题，此模式完全没解决。

**模式二（Stage A，`credit_mode='game'`）**：数据侧预先算好跨局折扣回报

\[
G_k = \sum_{j \ge k} \gamma^{\,j-k} R_j
\]

\(\gamma=1\) 时有闭式分解 \(G_k = pts[\text{最终顺位}] - \mathbb{E}_{\text{GRP}}[pts \mid \text{第 } k \text{ 局开始}]\)，即"终局真实点数 − 局前 GRP 期望"，GRP 期望自动充当**控制变量**（降低方差）。实测结论：**无增益、方向偏负**——说明"看不到长期结果"不是瓶颈。

**模式三（Stage B，`objective='iql'`）**：\(\gamma\) 变成 Bellman 链上**每决策步**的折扣，奖励经 \(V(s')\) 的 bootstrap 逐步向前传播（见 §7.3）。一场约 190 个决策点，\(0.997^{190} \approx 0.57\)，即整场回报仍有一半以上能传到开局。

## 7. 训练目标的三代演化

### 7.1 第一代：MC 回归 + CQL 正则（cql_mc 路径）

**通俗版**：把每个决策点的"人类实际选择"当作标准答案，让 Q 网络对这个动作的打分逼近 \(\gamma^{n_i} R_k\)，同时用 CQL 项压制"数据里没见过的动作"的 Q 值，防止网络瞎编。

**严格版**：

\[
L(\theta) = \tfrac{1}{2}\,\mathbb{E}_{\mathcal{D}}\Big[\big(Q_\theta(s,a) - \gamma^{n_i} R_{k(i)}\big)^2\Big]
+ \lambda_{\text{CQL}}\,\mathbb{E}_{s}\Big[\log\sum_{a'} e^{Q_\theta(s,a')} - \mathbb{E}_{a\sim\mathcal{D}}[Q_\theta(s,a)]\Big]
+ \lambda_{\text{aux}} L_{\text{rank}}
\]

第二项即 **CQL（保守 Q 学习）**：让"所有动作里 Q 最大值"（logsumexp）压低，而"数据里实际发生的动作"的 Q 抬高，净效果是未访问动作的 Q 被系统性压低。

**实测瓶颈**：五个轮次的对照实验（重复 epoch / 视角增强 / 收紧名单 / 换奖励口径 / 调 CQL 权重）全部无增益 → **问题不在数据或超参，而在目标形式本身**：这是一个"逐样本回归"，Q 对没发生过的 (s, a) 组合没有定价能力，argmax 决策实际停留在行为克隆水平。

### 7.2 第二代：跨局信用分配（Stage A，已否决）

把样本目标从"本局奖励"换成"跨局折扣回报后缀和" \(G_k\)（§6.2 模式二）。五层验证全过（闭式恒等误差 8.9e-16）、训练零额外 GPU 成本，但**判定无增益**。结论：瓶颈不是"看不到长期结果"，而是**没有价值传播与政策改进机制**。

### 7.3 第三代：IQL（Implicit Q-Learning，当前主线）

**通俗版——IQL 在解决什么问题**：离线学习最大的坑是"人类没走过的路，Q 网络只能瞎猜"。常见的修补（让 Q 取 max）会因为网络高估而爆炸。IQL 的巧妙之处：**永远不显式取 max**。它用两个网络分工——

- \(V(s)\)：一个"局势裁判"，只参考**人类实际走过的选择**的价值（所以永远不会被没走过的路带偏）；
- \(Q(s,a)\)：一个"动作打分器"，通过 Bellman 方程从裁判那里学习未来价值；
- 最后用"Q 比 V 高多少"作为**优势**，给人类实际选择加权，提炼出改进版策略。

整个学习闭环里没有一步需要对"没走过的路"取 max，所以稳定。

**严格版**：数据 \(\mathcal{D} = \{(s_t, a_t, r_t, s_{t+1}, d_t)\}\)（\(r_t\) 仅局边界非零，\(d_t\) = 终端标志），\(\gamma = 0.997\)。

**① \(L_Q\) —— Bellman 回归（[train.py#L560-L569](mortal/train.py#L560-L569)）**

\[
L_Q(\theta) = \tfrac{1}{2}\,\mathbb{E}_{\mathcal{D}}\Big[\big(Q_\theta(s,a) - y\big)^2\Big],\qquad
y = \begin{cases} r_t, & d_t = 1 \\ r_t + \gamma\, V(s'), & d_t = 0 \end{cases}
\]

目标端 stopgrad。**这是"跨局信用分配"在 IQL 里的实现方式**：第 \(t\) 步的 Q 通过 \(V(s')\) 从第 \(t+1\) 步借价值，一局结束后自然借到下一局——不再需要后缀和。

**② \(L_V\) —— expectile 价值回归**

\[
L_V(\eta) = \mathbb{E}_{\mathcal{D}}\Big[\,\big|\tau - \mathbf{1}\{\bar{Q}(s,a) < V_\eta(s)\}\big|\cdot\big(\bar{Q}(s,a) - V_\eta(s)\big)^2\Big]
\]

其中 \(\bar{Q}\) 是 EMA 目标网络（参数每步向在线网络做 0.995 的指数滑动平均，"缓慢跟拍"以稳定目标）。关键实现约束（曾因违反而返工）：**期望只对数据中实际执行的动作 \(a\)** 取（Kostrikov et al. 2021 式 9），不对全部合法动作取。

**③ \(L_{\text{AWR}}\) —— 优势加权策略提取**

\[
L_{\text{AWR}}(\theta) = -\,\mathbb{E}_{\mathcal{D}}\Big[w(s,a)\,\log \pi_\theta(a\mid s)\Big],\qquad
w(s,a) \propto \exp\!\Big(\frac{Q_\theta(s,a) - V_\eta(s)}{\beta}\Big),\;\; \beta = 3
\]

**总损失**：\(L = L_Q + L_V + L_{\text{AWR}} + 0.2\,L_{\text{rank}}\)（CQL 项关闭）。

**τ 的角色**（v3 实验的核心变量）：

- \(\tau \to 1\)：\(V\) 是 \(\bar{Q}\) 在数据动作上的高分位 ≈ "近似取 max"（强乐观）；
- \(\tau = 0.5\)：权重对称，\(L_V\) 退化为普通 L2 回归，\(V = \mathbb{E}_{a\sim\pi_\beta}[\bar{Q}(s,a)]\)（行为均值）；
- \(\tau > 0.5\) 的不对称有一个**实测出的坑**：当价值在增长期，\(V\) 持续落后于目标 → 残差系统性为正 → 被权重 \(\tau\) 强势上拉、负残差只被 \(1-\tau\) 弱势下拉 → 价值尺度**指数漂移**（v2 用 \(\tau=0.7\)：目标尺度每 ~3.2 万步翻一倍，10 万步膨胀 60 倍，模型被毁；\(\tau=0.6\) 只减半、仍发散；**唯一验证的稳定修复是 \(\tau=0.5\)**，v3 采用）。

> **通俗总结 v3**：\(\tau=0.5\) 时 IQL 的"乐观取高分位"特性被完全关闭，剩下的本质是"fitted-Q 价值迭代 + 优势加权模仿"——先用 Bellman 方程把价值沿决策链传播（这解决了"看不到未来"），再用优势权重挑出"人类选择中相对更好的那些"来加强模仿（这提供了超越行为克隆的机制）。代价是放弃了"隐式 max"的乐观性——这正是本轮实验要回答的科学问题：**在稳定的训练条件下，离线价值学习能否带来强度增益？**

> **2026-10-16 判定（答案：不能）**：v3 干净轮（τ=0.5）双向 ladder 5000 sets + block bootstrap 给出 **δ=+0.646，95%CI[−0.35,+1.63]（t=+1.09）**——按预注册守则（CI 下界 >0 才算赢）判"无结论"，与 Stage A 合并，**目标形式改造两子路线全部关闭**。归因：基线 B 的局内 MC 回传本就近全权重（每局 16 个决策点、局内折扣 0.997¹⁶≈0.95），跨局共同分量（std≈1.2）被全场 ~190 个决策摊薄（单决策 SNR≈1:10），且 AWR 在近最优专家数据（top1 0.8167）上权重≈均匀——瓶颈在数据分布的信息天花板，不在目标函数。holdout top1 0.8167 为历轮最高但未转化为强度，再次印证"更像人 ≠ 更能赢"。

## 8. 统计评估方法

### 8.1 通俗版：怎么判断"新模型真的更强了"

麻将单局结果随机性极大（"牌运"）。项目的做法是让新旧模型**在同一批"牌山"上打大量对局**（固定随机种子 → 牌山完全一致），比较期望点差。即便如此，也要用统计检验防止"碰巧赢了"。

### 8.2 严格版

**配对对抗（ladder）**：挑战者 C 与卫冕者 B 各打 \(N\) 个半庄（双向各 5×500 sets），每半庄记录点差 \(\delta_i\)。固定种子使两模型面对**完全相同的发牌**，天然构成配对样本。

**统计量**：

\[
\bar{\delta} = \frac{1}{N}\sum_{i=1}^N \delta_i, \qquad
SE = \frac{s_\delta}{\sqrt{N}}, \qquad
95\%\text{CI} = \bar{\delta} \pm 1.96\,SE
\]

**判进标准**：bootstrap 95% CI **下界 > 0**（比点估计显著更严格）。

**分块 bootstrap**：把对局按种子块分组，块内重抽样估计 CI，消除"种子块内相关"导致的 SE 低估。

**种子块轮换纪律**：每轮实验用全新的种子块（如 220000/230000），因为同一批种子块被多代模型反复比较会引入"牌山选择偏差"——早期实验实测过这种虚高。

|---|---|---|---|

## 9. 工程可靠性实践

这些实践大多来自真实事故，是本项目方法论的重要部分：

1. **冒烟测试必须含"数值型行为门禁"**：只检查"不崩溃、跑得完"是不够的。Stage B v1 首轮冒烟结构项全过，但模型实际已被打坏（2k 步即可从 test_play 的 avg_rank 看到），烧掉 11.5 小时 GPU 后才发现。v2 起门禁包含：test_play avg_rank ≤ 2.60、holdout top1 ≥ 0.78、logsumexp_q 绝对值 ≤ 10。**正是这些门禁在 v2 冒烟当场抓住了第二处实现缺陷**（L_V 误用全体合法动作）。
2. **测试要验"设计意图"而非"实现现状"**：首版数据自检用"iql 的 r_t 分布 == 旧口径逐样本值"当正确性质，恰恰放过了 r_t 被重复计入 16 倍的 bug。断言必须对照设计文档独立推导。
3. **fp32 纪律**：AMP（fp16 混合精度）下 BatchNorm 的滑动统计量会在溢出的那次前向就被写坏且不可恢复，此后前向永远 NaN。事故后本项目主训练轮固定 `enable_amp=false`。
4. **NaN 三重防护**：存盘前扫描全部权重/优化器/BN 缓冲的非有限张量；TB 直方图先过滤非有限值（否则直接打死训练进程）；链式脚本检查训练退出码，非 0 跳过判定。
5. **冒烟时间尺度要覆盖现象时间尺度**：价值漂移的倍增周期 ~3.2 万步，2k 步冒烟对它完全无感——定位这类慢漂的最便宜手段是"单旋钮 3 万步探针"（5 臂 × 30k 步 ≈ 4.5h），远胜反复烧 11.5h 的正式轮。
6. **评测种子固定 + 日志目录隔离**：ladder 多卡并行必须用独立日志目录（脚本会删目录）；评测种子每轮轮换。

### 10.2 术语表

| 术语 | 含义 |
|---|---|
| **kyoku（局）** | 麻将的一局；本项目奖励的结算单位 |
| **决策点** | 一个玩家需要做选择的状态时刻 |
| **行为策略 \(\pi_\beta\)** | 产生训练数据的人类玩家的（混合）策略 |
| **MC（Monte Carlo）** | 用完整观测回报直接回归，不做中间 bootstrap |
| **Bellman 方程** | \(Q(s,a) = r + \gamma\,V(s')\)：当前价值 = 即时奖励 + 折扣后的未来价值 |
| **bootstrap** | 用自己（或目标网络）的估计值当回归目标，价值沿链传播 |
| **expectile** | 分位数的 L2 版本：\(\ell_\tau(u)=\|\tau-\mathbf{1}\{u<0\}\|\,u^2\) 的最小解 |
| **AWR** | Advantage-Weighted Regression：按优势指数加权模仿数据动作 |
| **EMA / polyak** | 目标网络参数向在线参数做指数滑动平均，稳定回归目标 |
| **CQL** | Conservative Q-Learning：压低分布外动作 Q 值的正则 |
| **GRP** | Game Rank Predictor：输入按局前缀的 7 维分数形势（全局局号/本场/供托/四家点数），用 GRU 预测终局顺位排列（24 类）的网络 |
| **ladder** | 两模型固定种子配对对抗的强度判定流程 |
| **块 bootstrap** | 按对局块重抽样的置信区间估计，处理块内相关 |
| **暖启（warm start）** | 从已有 checkpoint 继承权重继续训练 |
