# AI similarity：本项目 S6c vs 官方 Mortal v3（2026-11-13）

## 0. 一句话

在同一批人类 holdout（79,098 个决策点）上，**S6c 与官方 Mortal v3 的 argmax 一致率 92.1%，
与人类动作的 top1 完全持平（0.8161 vs 0.8158，Δ = +0.03pp ± 0.09）**。
⇒ 本项目**不是"没追上官方"，而是复现到了官方 v3 的水平**；分歧处两者能力等价（McNemar n.s.），
且 S6c 在**立直决策上系统性更好（+5pp）**。

⚠️ 边界：v3 是 2023-03 的权重；官方现役是 4.1c（v4 obs）。**与 4.1c 的差距本报告无法回答。**

## 1. 为什么做这个诊断

社区模型卡（`VoidShine/mortal-298k`）报 "AI similarity 83%–92% on mjai.ekyu.moe"。
查证其口径：`mjai.ekyu.moe` 的分析报告「元数据」页自带「与 Mortal 的一致率」，
作者是把自家模型的牌谱提交到官方在线服务、读该字段得到的；**官方从不公开权重**。

本项目此前只有「相对人类」的指标（top1 0.8198）与「相对 akochan」的绝对锚点（+0.00±1.68），
从未测过「相对官方 Mortal」。本诊断补上这一坐标。

## 2. 方法（比社区口径更严格）

| 项 | 社区做法 | 本报告 |
|---|---|---|
| 参照系 | 官方在线服务（mjai.ekyu.moe，需 Turnstile，批处理受限） | 官方血缘权重 **`hhim8826/mortal3-b40c192`**（HF，AGPL-3.0）：v3 / 192ch / 40blocks / 10.77M 参数 / 2023-03-25 |
| 比较对象 | 自家模型的**对局牌谱**（局面分布是自博弈分布） | **同一批人类 holdout 的决策点**（分布=人类实战） |
| 对齐 | 服务端逐手比对 | **逐文件配对**：同一个 `.json.gz` 分别用 `version=3` 与 `version=4 + s6c` 解码，逐位校验 `actions/masks` 相同后才比 argmax |

为什么不能"两个 DataLoader 并行跑"：`FileDatasetsIter` 的 `file_list`/`buffer` 都用
`random.shuffle`，且 v3/v4 的 obs 编码走不同分支（不是子集关系），跨文件会漂移
（实测第 18 批错位）。故改为**逐文件**配对，并在 `dataloader.py` 加了可选 `seed=`
（缺省 `None` = 旧行为不变）。

## 3. 结果（两个独立 seed，各 60 文件）

| seed | 样本数 | argmax 一致率 | top1 官方 v3 | top1 S6c | Δ(S6c−v3) | McNemar |
|---|---:|---:|---:|---:|---:|---|
| 20261009 | 40,513 | **0.9201 ± 0.0013** | 0.8159 ± 0.0019 | 0.8157 ± 0.0019 | −0.02 pp ± 0.13 | b=1363 / c=1371，χ²=0.0，n.s. |
| 20261113 | 38,585 | **0.9213 ± 0.0014** | 0.8157 ± 0.0020 | 0.8165 ± 0.0020 | +0.08 pp ± 0.13 | b=1314 / c=1283，χ²=0.3，n.s. |
| **合并** | **79,098** | **0.9207** | **0.8158** | **0.8161** | **+0.03 pp ± 0.09** | 等价 |

分歧结构（seed1）：分歧 8.0%，其中「仅 S6c 对」42.1%、「仅 v3 对」42.4%、「两个都错」15.5%。
**完全对称** ⇒ 两者不是"一强一弱"，而是在不同局面上各错各的。

### 3.1 分动作类型（两个 seed 同向）

| 人类动作 | seed1 n | seed1 v3 / S6c | seed2 n | seed2 v3 / S6c |
|---|---:|---|---:|---|
| 打牌（<34） | 31,372 | 0.7810 / 0.7803 | 29,893 | 0.7807 / 0.7809 |
| **立直（37）** | 447 | **0.8255 / 0.8837（+5.8pp）** | 457 | **0.8621 / 0.9081（+4.6pp）** |
| 鸣牌/其它 | 8,157 | 0.9375 / 0.9361 | 7,698 | 0.9362 / 0.9367 |
| 和了（43） | 537 | 1.0000 / 1.0000 | 537 | 1.0000 / 1.0000 |

**S6c 的唯一结构性优势是立直**（+4.6~5.8pp，合并约 +5pp，n≈900，3σ 级）。
这与 S6c 注入的 2 行特征（自家向听/实战有效牌数）直接相关——立直判断正是"我离听牌多远、还剩几张"的函数。
打牌上两者完全持平（差 <0.1pp），说明 S6c 的收益集中在"何时立直"这一决策上。

## 4. 结论与解读修正

1. **复现成功，不是失败**。此前用 anchor3（+0.00 vs 3×akochan）推断"我们只有常客水平"，
   容易读成"训练不到位"。本报告给出更准确的定位：**人类一致性 = 官方 v3**。
2. **92.1% 的一致率**落在社区模型卡报的 83%~92% 上沿；考虑到我们用的是"人类局面 + 严格逐文件配对"
   （比"自博弈牌谱 + 在线服务"更苛刻），这个数值符合预期。
3. **官方迭代的真实幅度**：官方 4.0→4.1c 为 +0.254pt（社区转述），我们的 S6c 换代为 +0.422。
   在"人类 top1"这个坐标上，S6c 与 v3 的差距已为 0 ⇒ **后续任何改动都应以 v4 系为参照**，
   否则无法判断"提升"是真提升还是补上了 v3→4.x 的代差。
4. **与 4.1c 的差距未知**，这是本报告最大的边界。要回答它，需要 v4 系权重（HF 暂无可靠镜像）
   或在线服务（Turnstile 限制）。

## 5. 复现

```bash
cd mortal
# 1) 取参照权重（43.4 MB，AGPL-3.0）
curl -L -o checkpoints/_ref/mortal3_b40c192.pth \
  https://hf-mirror.com/hhim8826/mortal3-b40c192/resolve/main/mortal.pth
# md5: 098c59b80639ba0e5bae375a92f0bfb5

# 2) 跑诊断（GPU0，60 文件 ≈2 分钟，40k 决策点）
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0 MORTAL_CFG=config.s6c.toml \
  python -u diag_ai_similarity.py --files 60 --seed 20261009
```

产物：`mortal/logs/ai_sim_20261113.log`（seed1）、`mortal/logs/ai_sim_seed2_20261113.log`（seed2）。
