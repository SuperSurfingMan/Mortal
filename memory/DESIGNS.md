## §1　状态依赖押し引き守卫（Guard-P2）设计

> 出处：原 `memory/DESIGN_guard_statewise_20261027.md`，逐字并入本合订本（原始版本见 `backups/memory_docs_20261122/DESIGN_guard_statewise_20261027.md`）。

# 设计：状态依赖的押し引き守卫（Guard-P2，2026-10-27）

> ⚠️ **2026-11-03 注记（过期声明）**：本文的前提「λ=10 是唯一被证明有效的机制（+0.78）」**已不成立**——
> 那个 +0.778 是 `risk` 双乘 P(听) 的旧口径产物；修正后在全新种子上四臂全是 NO-CONCLUSION，
> 线上默认已改 `MORTAL_GUARD_LAMBDA=0`。本文**保留为设计/实现记录**（Guard-P2 的机制、代码与回归仍可用），
> 但结论（「相对 λ=10 提升 0.3~0.8」）不要引用。详见
> `tools/read_model/docs/GUARD_RISK_FIX_20261102.md` 与 MEMORY §3.13/§3.17。
>
> 目标（历史）：在**不改模型、不重训**的前提下，把线上守卫从「全局固定 λ」升级为「按局面定权」，
> 拿到 **+0.3~0.8 pt/半庄**（相对当时的 λ=10 基线）。这是当时唯一被证明有效的机制（λ=10 → +0.78）
> 在它自己没覆盖的维度上的自然延伸。

## 0. 为什么是这条线（前情提要）

- 剂量曲线（每臂双向 64000 半庄）：λ=5 +0.550（CI 跨 0）、λ=7.5 +0.712、**λ=10 +0.778（峰值）**、
  λ=20 −0.496、λ=50/τ=0.03 −2.663 ⇒ **线性风险惩罚已饱和**：再加大 λ 就开始「用和了换放铳」。
- 行为对照：agari 0.217→0.207（−4.6%）、houjuu 0.130→0.111（−14.6%）——
  **代价集中在和了率**，说明「无差别扣分」在不需要弃和的局面里也在扣。
- 因此增量只能来自**局面条件**：同样的 risk，在「南场第 2 局、我 1 位领先 12000」和
  「オーラス、我 4 位落后 8000」应当值不同的 λ。
- 已否证的近亲：EV 重排（`+β·ev_norm`）是 obs 里已有 SP 表的重加权，Q 与 SP-EV 排序 94~99% 一致
  ⇒ 冗余（MEMORY §3.12c）。**本设计不用 SP，只用「Q 里没有的信息：对手打点与顺位压力」**。

---

## 1. 形式化

当前（G3）：

```
Q'(t) = Q(t) − λ · max(risk(t) − τ, 0),      risk(t) = Σ_j P(听_j)·P(待牌_j = t)
```

升级后（G4，两种成分可独立开关）：

```
Q'(t) = Q(t) − λ0 · w_state(s) · max(risk_w(t) − τ, 0)

w_state(s) = clamp( w_opp · w_turn · w_score , 0.5, 2.0 )      # 全局局面权重，λ0 = 10
risk_w(t)  = Σ_j P(听_j)·P(待牌_j = t)·v_j                     # 逐对手价值权重（可选）
```

- `v_j`：对手 j 这一手的**打点档位**（`1.0` 默听/不明、`1.3` 立直、`0.7` 副露）——
  在 `risk_w` 里体现「放铳给立直家更贵」，不改总惩罚量级；
- `w_opp`：`1.0 / 1.12 / 1.24 / 1.36`（立直家数 0/1/2/3）——多家立直时同一 risk 更贵；
- `w_turn`：`0.88`（巡目 ≤6）/ `1.0`（7~12）/ `1.18`（≥13）——早巡还有翻盘时间，弃和的机会成本高；
- `w_score`：**待定，见 §3 的 A/B**（点差是最可能出增益也最容易出错的一项）。

三档系数都**不是自由参数**：先验方向固定（多立直↑、晚巡↑、领先↑/垫底↓），
每项只留一个「强度」旋钮，离线只调强度不调符号。

## 2. 三个成分的证据与优先级

| 成分 | 证据 | 先验 | 实现成本 | 风险 |
|---|---|---|---|---|
| **A. `risk_w`（逐对手打点）** | 放铳损失 = 打点；立直家平均 5200、副露 3000、默听 3500（本库 `algo/point.rs` 可比对） | 中 | 低（只改 risk 聚合） | 低（不改变「要不要弃」的总量，只改变「怕谁」） |
| **B. `w_opp`（立直家数）** | 现守卫已用三家 union，但没区分「1 家 vs 3 家」；P0-B 显示 `turn≥8 有立直家` 时 fixable 占 2.59% | 中高 | 低（obs 里 `OFF_RIICHI` 已有） | 低 |
| **C. `w_turn`（巡目）** | 晚巡放铳无法翻盘；早巡弃和代价高 | 中 | 低（用 `tiles_seen` 总数即可，无需精确巡目） | 中（与 w_score 相关） |
| **D. `w_score`（点差）** | S6a 证伪了「把点差当**输入**喂网络」，但这里是**推理期惩罚调制**，机制不同 | 低~中 | 中（需解析 obs 的 scores 行，一次性探针） | **高**（易与 Q 的顺位价值重复计算） |

**执行顺序**：A+B → C → D（逐项做，每步都能单独判）。前两步即使全败也便宜。

## 3. 点差项（D）的两种写法，先离线二选一

**D1 规则分档**（简单、可解释）：

```
领先 ≥ 12000 → w_score = 1.20      # 守住即可，多弃
落后 ≥ 12000 且剩 ≤2 局 → 0.75     # 必须推
其余 → 1.0
```

**D2 边际价值**（更原理化，但需要标定）：

```
w_score = clip( (∂E[rank-pt]/∂score) / (∂E[rank-pt]/∂score)|_even , 0.7, 1.4 )
```

其中 `∂pt/∂score` 用「与相邻名次的点差」近似：`≈ 1/(1 + |Δscore to 邻位| / 8000)`。
意义：离名次边界越近，1 点分数越值钱 → 同样的放铳更贵 → 更该弃。

- **离线判定口径**：在 20k 固定集上，若存在某档系数使 `deal_top1` 不升（±0.3pp 内）而
  **SP `p_win` 或 `agari` 代理指标显著上升**，则该写法有「支配性」；否则淘汰。
- 若两者都平庸，先只上 A+B+C（D 留待后续）。

## 9. M1+M2 结果（2026-10-27）

**M1 完成**：`mortal/guard_state.py` + `tools/test_guard_state.py`（**ALL PASS**）。
两个关键实测发现（已写进回归）：
1. **v4 obs 的分数是已旋转到本家视角的**：`rank==0 ⟺ scores[:,0] 为最大`（100%，n=1256）；
   行号 = `7..14`（4 家 × 2 行），名次 one-hot `15..18`，局数 `19..22`；
2. 分数和 = `100000 − 1000×供託`（立直棒不在 scores 里），且约 **8.6% 的样本存在平分** ⇒
   `lead/deficit` 改用「对最高其他人」的口径（避免名次索引在平分处不自洽）。

**M2 结果（20k 固定集，seed 20261016，基线 = 固定 λ=10）**：

| 配置 | 变化率 | deal_top1 | p_win | 相对基线的汇率 |
|---|---|---|---|---|
| fixed λ=10 | 0 | 0.0094 | 0.0943 | — |
| risk_w（v_riichi=1.3） | 0.26% | 0.0093 (−1%) | 0.0941 (−0.2%) | ≈ 5pp deal / 1pp pwin |
| w_opp | 0.19% | 0.0093 (−1%) | 0.0942 (−0.1%) | — |
| w_turn | 0.50% | 0.0091 (−3%) | 0.0942 (−0.1%) | — |
| **w_opp×turn** | 0.70% | **0.0089 (−5.3%)** | 0.0941 (−0.2%) | **25pp / 1pp** |
| w_opp×turn×score | 0.56% | 0.0092 (−2%) | 0.0941 (−0.2%) | — |
| w_score only | 0.34% | 0.0095 (+1%) | 0.0943 (0) | — |

**判读**：全部配置的 `p_win` 都不升（−0.1~−0.2%），**没有一条满足准入条件**
（`deal ≤ fixed+0.3pp` 且 `p_win ≥ fixed+0.10pp`）。而最好的 `w_opp×turn` 的交换率
（deal −5.3% / pwin −0.2% ≈ 25:1）与固定守卫自身的（−29% / −1.05% ≈ 27:1）**几乎相同**
⇒ **状态重分配只是沿同一条 frontier 移动，没有带来更好的交易**。

结合 S6a 的教训（点差是 Q 已有信息）可读作：**Q 已经按局面给风险定价了**，
外挂的 `w_state` 与「把 λ 调大一点」等价。

**决定（按设计 §7 的终止条件）**：**不上 16k 臂**（省 5~8 h），Guard-P2 记为 neg；
`guard_state.py` / 回归 / `eval_guard_state.py` 保留为基建（后续若要按「对手打点」重估可用）。

## §2　搜索/专家迭代（EI）三档设计

> 出处：原 `memory/DESIGN_search_ei_20261028.md`，逐字并入本合订本（原始版本见 `backups/memory_docs_20261122/DESIGN_search_ei_20261028.md`）。

# 设计：用搜索 / 专家迭代突破 BC 天花板（2026-10-28）

> 前提（已测）：模型的残差**不是标签歧义而是高置信分歧**——top1 0.747 但 top3 0.951 / top5 0.975，
> 错误处 `Q(top1)−Q(human)` 中位 **+0.72**、仅 4.6% 落在 0.05 的近似平局内（§7 of STAGE_SUMMARY）。
> ⇒ 继续提高与人类的一致率不会变强；要变强必须让「**价值估计**」比 Q 更准，再用它去改策略。

---

## 0. 一句话

麻将的不完全信息 + 4 人博弈让通用 MCTS 性价比很低；但本项目有三件别人没有的资产——
**SP 单人 DP（自带在 obs）**、**A2c 对手后验（AUC 0.97）**、**高速 4 席模拟器（2.8 局/s/GPU）**——
所以正确的做法是**结构化搜索 + 专家迭代（Expert Iteration, EI）**，而不是照搬 AlphaZero。

```
循环：现策略 π_k  →  在若干状态上用「结构化搜索」给出更好的动作/价值  →  蒸馏回网络 π_{k+1}
```

三个可落地的档位，按成本从低到高，**每一档都能独立判定、独立止损**。

---

## 1. 为什么 Q 已经"没有搜索空间"，但 EI 仍有空间

- 策略就是 `argmax_a Q(s,a)`，所以「用 Q 改进 Q」是恒等变换；
- 但 Q 是**模仿人类 + MC 回报**学出来的：它在「人类怎么做」上很准，在「怎么做更强」上未必；
- EI 的关键是提供一个**不同于 Q、且更接近真实期望顺位收益**的目标 `T(s,a)`；
- 我们的三个候选 teacher，恰好覆盖三种成本：

| 档 | teacher 形态 | 依赖 | 单状态成本 | 上限 |
|---|---|---|---|---|
| **A** | 自博弈 + 真实 MC 回报（无显式搜索） | arena + 现有训练管线 | ~0（复用对局） | 中：换个状态分布，不改单点决策 |
| **B** | **1-ply 结构化 expectimax**（SP 进攻 + A2c 防守，在 rank-pt 单位合成） | SP（obs 内）+ A2c + 标定 | 微秒~毫秒 | 中高：能翻转高置信分歧 |
| **C** | **短 rollout EI**（K 候选项 × M 次 k 步模拟 + Q bootstrap） | arena + 并行采样 | 10~50 ms | 高：真正的策略改进算子 |

---

## 2. 档 A：自博弈 + MC 回报（最便宜，先做）

**做法**
1. 用现役模型（S6c+守卫）自对局 **N=20k~50k 局**（`OneVsThree`/`py_vs_py` 已能 dump mjai 日志到 `log_dir`）；
2. 用 `GameplayLoader` 读回自产日志 → 与人类数据同构的样本（obs/action/mask）；
3. **目标换成纯 RL**：`L = (Q(s,a) − G_t)²`，`G_t` 为从该步起的真实 rank-pt 折扣回报（现有 `env` 已算）；
4. 混采比例：人类数据 : 自博弈数据 = 4:1~10:1（防分布漂移），100k 步暖启。

**为什么可能有效**：人类数据里「人类不会走的局面」永远没有样本；自博弈会把模型带到它自己会遇到的分布上，
并给出**真实回报**（不是模仿标签）。

**风险**：无搜索的自博弈容易自我强化（同质化），且 rank-pt 单局方差极大（σ≈1.2/半庄分摊到 ~190 决策）。
**止损**：holdout 的 top1 只作监控（不作为判据）；主判据仍是 **16k sets 标准臂**（δ_min≈0.43）。

**成本**：生成 50k 局 ≈ 5 h（2 卡）；训练 100k 步 ≈ 7 h；臂 4~8 h ⇒ **约 1 天**。

---

## 3. 档 B：1-ply 结构化 expectimax（性价比最高）

**核心**：把「进攻」与「防守」放进**同一个 rank-pt 目标**，而不是在 Q 上做线性扣分（后者已四次否证）。

对每个候选打牌 `a`：

```
V(s,a) = E_draw[ V_off(s') ]  −  Σ_j P(听_j|s')·P(待牌_j = a|s')·E[loss_pt_j] · κ
```

- `V_off(s')`：**直接用 obs 里的 SP 表**（它本来就是「打完这张之后、在剩余摸牌内的期望价值和」的精确 DP，
  单位是点）——不需要我们再实现一次摸牌枚举；
- 防守项：A2c 的 `P(听_j)`、`P(待牌_j = t)`，乘 `E[loss_pt_j]`（立直 5200 / 默听 3500 / 副露 3000，可从日志标定）；
- `κ`：**唯一的标定参数**（点 → rank-pt 的汇率），用**离线回归**拟合：
  在人类日志上，用 `(ΔV_off, risk·loss)` 预测「本局最终 rank-pt 变化」，得到 κ 与偏置。

**为什么这次不同**：前四次（guard λ / EV 重排 / Guard-P2 / 加性损失）都是**在推理时给 Q 加一项**；
这里是把 V 变成**训练目标**（`T(s) = argmax_a V(s,a)`，软标签用 softmax(V/τ)），去改网络的**判断**。

**只在高价值状态上算**：`|Q(top1) − Q(top2)| < 0.5` 或「有立直家 / 巡目≥8」的状态（约占 20~30%），
其余状态沿用人类标签 ⇒ 保持数据分布，避免整体漂移。

**成本**：teacher 实现 1 天（复用 `ev_rerank.sp_features` + `guard_state/defense_guard` 的 risk）；
生成 20k~50k 条「改进目标」 ≈ 1~2 h；蒸馏 100k ≈ 7 h；臂 4~8 h ⇒ **约 2 天**。

**止损**：先在 20k 固定集上对比 `T` 与人类标签的差异率与方向（应 <30% 且集中在高置信分歧），
若 teacher 在 90% 的状态上等于人类 ⇒ 没有增量，直接停。

## 4. 档 C：短 rollout EI（上限最高，最后做）

**做法**：对候选 `a`（最多 4 个），做 `M=16~32` 次 **k 步 rollout**（k≈4~8 次摸打），
每个 rollout 用现策略打四家、牌山从未见牌里均匀采样，到 k 步后用 `Q(s_k, a_k)` bootstrap 终值；
取 `argmax_a` 的 rollout 均值作为 target。这是标准的 policy improvement operator。

**成本估算**：一次决策 ≈ 4 候选 × 24 rollout × 8 步 ≈ 770 次决策前向 ≈ 8 局等价；
按 2.8 局/s/GPU ≈ **3 s/状态**。做 20k 状态 = 17 卡时（约 2 h × 8 卡）。

**为什么最后做**：它依赖两个前提——(a) 观测量足够支撑 k 步模拟（有 A2c 与 SP）；
(b) 值函数足够准（否则 bootstrap 误差会淹没改进）。档 B 正好验证这两点。

## 8. 档 B 的 20k 离线对照（2026-10-28，已做 → **teacher 不合格，暂停蒸馏**）

`tools/ei_teacher.py`（S6c/956k + A2c risk + SP 表，20,000 打牌决策，κ ∈ {0.001,0.002,0.004}）：

| 指标 | 值 |
|---|---|
| Q 与人类一致 | **0.7468** |
| teacher 与人类一致 | **0.537**（κ 几乎无影响：0.537/0.539/0.540） |
| 在 Q≠人类 的 5,110 个状态上（κ=0.002） | 站 Q **34.1%** / 站人类 **35.2%** / 两者都不是 **30.7%** |
| 按 Q 边际分层 | 低边际：站人 54% / 站 Q 20%；高边际：站 Q 48% / 站人 20% |

三个候选的质量（同一批 Q≠人类 状态）：

| 候选 | SP EV（点） | p_win | risk | risk×loss（点） |
|---|---|---|---|---|
| 人类 | 1022 | 0.1285 | 0.0179 | 348 |
| **Q(top1)** | **703** | **0.0907** | **0.0145** | **275** |
| teacher | 1146 | 0.1453 | 0.0185 | 374 |

**两个结论**：
1. **teacher 作为全局目标不合格**：与人类只有 0.537 一致（远低于 Q 的 0.747），且 κ 从 0.001 到 0.004
   几乎不改决策 ⇒ 它被 SP 的「单人速度 EV」主导。**SP EV 不刻画人类的下注/顺位权衡**，
   直接蒸馏会把模型推向「纯速度」。
2. **但暴露了一个真问题**：在模型高置信分歧的状态上，Q 的选择相对人类是
   **EV −31%、risk −19%** —— 也就是**模型比人类更保守**（与「守卫让它更保守且更强」在自博弈里
   成立，不矛盾：自博弈里过度进取会被惩罚，人类场里未必）。
   这个偏差**方向明确但价值未知**（EV 与 risk 同时变，无法用手头单步指标裁决）。

**按预注册止损：档 B（SP-EV teacher）不进入蒸馏**。若继续，只有两条：
- **B′ 用结果拟合 teacher**：把 `V(a)` 的权重（EV 与 risk 的系数）用「本局最终 rank-pt」回归出来
  （而不是用 κ 猜），本质是「档 A 的价值拟合」；
- **C 短 rollout**：用真实对局结果做终值，绕开手写价值函数。

## 9. 档 C 的可行性结论（2026-10-28）：**可行，路径已找到**

原本担心「没有可用的中局模拟器」。实测 Python 侧暴露了所需 API：

```python
from libriichi.state import PlayerState
PlayerState(player_id)        # 空状态
st.update(event)              # 逐事件推进（mjai 事件字典）
st.encode_obs()               # 直接产出 v4 obs（1012 行）—— 可用于假想状态的策略推理
st.tehai / shanten / last_cans ...   # 状态查询
```

⇒ **一次 k 步 rollout 的完整链路可以全部在 Python 侧跑通**：

```
用日志前缀事件 → st.update(...) 还原到决策点 s
  for a in 候选打牌:
      st' = copy(st)（用「重放前缀 + 替换这一步」实现，见下）
      st'.update({type:'dahai', actor:me, pai:a, tsumogiri:...})
      之后 k 步：
        我方：从未见牌里采样摸牌 → update(tsumo) → encode_obs → 模型选打牌 → update(dahai)
        对手：用「日志里的后续真实动作」（shadow rollout，不做反事实）或模型近似
      到 k 步后：V = 折扣 rank-pt 增量 + Q(s_k, best) 的 bootstrap
  T(s) = argmax_a mean_rollout V
```

**关键实现细节（已知坑）**
1. **状态复制**：没有 `clone`，需用「同一批前缀事件重放到 s」来物化每个候选分支；
   为省时间可把前缀事件缓存，按需重放（一次重放 ~几十个事件，微秒级）。
2. **对手策略**：先用 **shadow**（照抄日志后续动作）——它无偏采样「对手的真实行为」但不对我方改变做出反应，
   会低估 risk；若要走强搜索，再换成「模型近似对手」。
3. **摸牌采样**：从 `st` 的未见牌（obs 的 tiles_seen）里均匀抽，**不要**用日志的真实牌山（那是上帝视角）。
4. **代价**：单候选单 rollout ≈ k×(encode_obs + 1 次前向) ≈ 8×(0.5ms+2ms) ≈ 20ms；
   4 候选 × 16 rollout ≈ 1.3 s/状态。20k 状态 ≈ 7 卡时 ⇒ 8 卡并行约 1 h。

**结论**：档 C 不再是「要改 Rust」的工程，而是 **1~2 天的 Python 工作**：
`tools/ei_rollout.py`（状态物化 + 采样 + 打分）+ teacher 落盘格式 + `train.py` 的 `target_mode='teacher'`。

## 11. 档 C 的详细实施规划（2026-10-28 定稿）

### 11.1 组件与数据流

```
日志(gz) ──► 事件流 ──► PlayerState 重放到决策点 s（seat r）
                              │
                    ┌─────────┴──────────┐
             候选 a ∈ 自家手牌        人类动作 a_h（对照）
                    │
             分支物化：重放前缀 + dahai(a)
                    │
        ┌───────────┴────────────┐
   我方回合                      对手回合
   encode_obs → 模型 Q → dahai   照抄日志事件（shadow）
   （摸牌用日志真实牌山）          │
        └───────────┬────────────┘
             直到：我方第 k 次打牌 / 本局结束 / 对手出现 call/ron（截断）
                    │
           终值 V(a) = 折扣 rank-pt 增量 + γ^k·Q(s_k, best)   ← 步骤 3 才接入
```

### 11.2 分步实施与验收

| 步 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **S1** ✅ | 状态物化 / 分支合法性 / obs 一致性 | `tools/ei_rollout.py --mode check` | 重放 0 异常、1052/1052 分支可推进（**已过**） |
| **S2** | **k 步 rollout 本体**（我方模型决策 + 对手 shadow + 截断判定） | `--mode rollout` | 分支完成率 >60%；截断原因可归因；耗时 <50 ms/分支 |
| **S3** | 终值：`Q` bootstrap（或真实点数），产出 `V(a)` 与方差 | 每状态 `{V[a], n, std, truncated}` | 人类动作的 V 与其实际结果方向一致（AUC>0.55） |
| **S4** | teacher 生成（20k 状态） | `teacher_targets.pkl`（key`: file+event_idx`） | teacher≠human 的比例 10%~40%；与 Q 的分歧可解释 |
| **S5** | 蒸馏训练 100k（`target_mode='teacher'`，只覆盖命中样本） | 新 ckpt | holdout 不退（−0.5pp 内）+ 16k 臂 CI 下界>0 |
| **S6** | 判定与归档 | MEMORY + 模板 | 新种子 600000/620000 |

### 11.3 实现约定（避免踩坑）

1. **摸牌**：用日志真实牌山（我方 tsumo 事件里的牌），不自行采样——它是「未见牌分布」的一次合法抽样，
   且能复用后续事件对齐；若需要多样本，才改为从未见牌均匀抽。
2. **对手 shadow 的合法性**：只接受 `tsumo/dahai/dora`；遇到 `chi/pon/kan/reach/hora/ryuukyoku`
   立即截断（我方改牌后对手行为本应不同，shadow 已失真）。
3. **截断处理**：截断分支不丢弃，而是把「截断时的 Q bootstrap」作为终值，并记录 `truncated=1`；
   S3 里单独统计「截断 vs 完整」的 V 分布，避免截断偏置。
4. **候选集**：只用自家手牌（`tehai>0`），通常 5~13 个；超过 8 个时按 Q 取前 8（搜索预算）。
5. **耗时预算**：每个我方回合 = 1 次 encode_obs（~0.5 ms）+ 1 次前向（~2 ms）；
   k=6 时单分支 ≈ 15 ms，8 候选 × 16 样本 ≈ 2 s/状态 ⇒ 20k 状态 ≈ 11 卡时（8 卡 ~1.4 h）。
6. **确定性**：不引入额外 RNG（摸牌用日志），保证同一状态同一分支可复现——便于 debug 与缓存。

### 11.4 失败模式与止损

| 现象 | 判读 | 动作 |
|---|---|---|
| 分支完成率 <30% | shadow 太脆（对手动作经常失效） | 改用「对手也用模型近似」或缩短 k |
| teacher 与 Q 分歧 <10% | 搜索没有新信息 | 停（与档 B 同样的结论） |
| teacher 与人类一致 <60% 且分歧方向全是「更激进」 | 重蹈档 B 的覆辙（SP 化） | 停，改 S3 的终值口径 |
| 人类动作 V 的 AUC <0.52 | 终值噪声过大 | 加 k 或加样本量；否则停 |

## 12. S2（k 步 rollout）实测结果与两个必须修的问题（2026-10-28）

### 12.1 两次实测

| 配置 | 状态 | 分支 | **完整率** | 截断原因 | ms/分支 | 完整分支终态向听 |
|---|---|---|---|---|---|---|
| k=6, 6 候选 | 20 | 120 | **5.0%** | pon 60 / hora 54 | 55.5 | −4.0（**异常**） |
| **k=2, 4 候选** | 20 | 80 | **50.0%** | pon 24 / hora 16 | 37.7 | 1.98（听牌 10%） |

### 12.2 问题一：截断**有偏**（比完成率低更严重）

95%（k=6）/ 50%（k=2）的分支死在**对手鸣牌或和了**上，而这些事件恰好携带
「我们改的这张牌是否被利用」的信息。现在的实现把它们当噪声 `break` 掉 ⇒
rollout 系统性丢掉了**风险侧信号**，只剩「我方手牌速度」——那就退化成了档 B 的 SP 化 teacher。

### 12.3 问题二：`hora` 未记录 `actor/target`，放铳信号被丢弃

`hora` 事件带 `actor`（赢家）与 `target`（放铳者）。`target == 我方` 就是**放铳**，
应作为终值的大负项，而不是 `break`。当前代码没有读这两个字段。

### 12.4 问题三：k=6 的终态向听 −4.0 说明长 rollout 状态被污染

正常向听范围 −1~6。k=6 出现 −4 说明某一类事件（很可能是 `reach` / `dora` / `ankan` 的顺序）
在分支里被错误应用，需要按事件类型逐类排查。

### 12.5 修正方案（A+B+C，约 1 小时）

| 修法 | 内容 | 预期 |
|---|---|---|
| **A. 记录结局** | `hora` 读 `actor/target`；`target==我方` ⇒ `deal_in=1` 且终值加大负项；`ryukyoku`/`end_kyoku` 记本局点数变化 ⇒ **直接用真实 rank-pt 当终值**（优先于 Q bootstrap） | 终值从"向听代理"变成真值 |
| **B. 区分鸣牌来源** | `pon/chi/kan` 若 `target==我方` ⇒ 合法（牌确实变了）继续推进；若 `target!=我方` 且该牌不在场上 ⇒ **跳过事件**而不是截断 | 完成率 50% → 70%+ |
| **C. k=2 起步** | k=2 已 37.7 ms/分支（20k 状态 × 4 候选 ≈ 1 h / 8 卡），先用 k=2 验证价值，再考虑 k=4 | 控制成本 |

### 12.6 下一步的验收（自洽性）

改成 A+B+C 后，用「**把人类当轮动作也作为候选**」做检查：
若人类动作的真实 rank-pt 终值在统计上优于其它候选（AUC>0.55），说明 rollout 终值可信，
可进 S4（teacher 生成）；否则说明 k=2 + shadow 信息量不足，需要加长 k 或把对手也换成模型。

**当前状态**：S1 ✅、S2 🔄（机制跑通，完成率/截断偏差/状态污染三项待修）。

`hora` 的 `deltas` / `target` 已接入（`val += deltas[seat]`、`deal_in = target==seat`）。
问题是 **k=2 只有 17.4% 的分支能走到本局结束**，而这 17.4% 基本都是「决策点恰在局末」的边界样本
（`end_kyoku` 直接命中、`val=0`）⇒ 自洽性比较全是平局，**检查无效**。

### 13.3 B（跳过鸣牌事件而非截断）**会污染状态，必须回退**

跳过一个 `pon`/`chi` 意味着叫牌者永远拿不到那张牌，后续他的手牌就与事件流不一致；
累积之后模型会「打出手里没有的牌」：
`RuntimeError: attempt to discard 1m from void`（k=99 跑到第 60 个状态崩）。
⇒ **B 回退为截断**（记录原因），改用「缩短视界 + bootstrap」来提升有效样本率。

### 13.4 C（k=2 起步）结论：太短，终值几乎不可用

k=2 的视界下，绝大多数分支既走不到和了/流局，也走不到危险事件 ⇒ 终值只有 0。

### 13.5 修正后的终值口径（下一步唯一要做的事）

```
V(a) = 若分支在视界内走到 hora/ryukyoku → 我方真实点数变化（deltas）
       否则 → Q(s_cut, best) 的 bootstrap（rank-pt 单位，与 GRP 对齐）
```

这样**每个分支都有值**，不再浪费 83% 的样本；同时也保留了真实结局的高质量信号。
实现要点：
1. 在 `rollout_branch` 里返回 `cut_obs`（截断点的 obs），由调用方批量前向取 `max_a Q`；
2. 截断（`chi/pon/kan/reach/hora`）时不做状态修补，直接返回 `ended=False` + `cut_obs`；
3. 自洽性检查改为 **配对比较 + AUC**（人类动作 vs 每个其它候选），不再依赖「双方都 ended」。

### 13.6 当前状态

S1 ✅ / S2 🔄（A 已接入、B 回退、C 需换 bootstrap 终值）/ S3 ⏳

## 14. 混合终值实测（2026-10-29）：口径跑通，但**自洽性 ≈0.52，未过门槛**

### 14.1 本次实现

```
V(a) = 分支走到 hora/ryukyoku → 我方真实点数变化 × PT2RANK(5e-5)
       否则（鸣牌/立直/视界耗尽）→ Q(s_cut, best) 的 bootstrap（rank-pt）
```

同时回退了 B（鸣牌/立直一律**截断**，不再跳过——跳过会污染状态）。

### 14.2 实测（271 状态 / 1079 分支 / k=2 / 4 候选）

| 指标 | 值 |
|---|---|
| 走到本局结束 | 146（**13.5%**），其中放铳 12 |
| bootstrap 分支 | 933（**86.5%**） |
| 无值分支 | 0 |
| 耗时 | 38.5 ms/分支 |
| **自洽性（人类 vs 其它候选）** | **胜 0.452 / 负 0.413 / 平 0.135（n=808）⇒ AUC≈0.52** |

### 14.3 判读：**k 步 shadow 的信息量不足**（未过 0.55 门槛）

两条互相独立的稀释：
1. **86.5% 的分支用 Q bootstrap**：这些分支的状态与原始状态只差 1~2 张我方打牌，
   `max_a Q` 几乎相同 ⇒ 只能产生噪声，不可能区分候选；
2. **13.5% 的真实结局只有 1 次抽样**：单局点数方差约 ±8000（≈±0.4 rank-pt），
   单样本无法分辨「人类更好」这种量级很小的差异。

### 14.4 结论与下一步（唯一正确的修法：**多采样**）

当前实现是「**确定性单样本 rollout**」（墙牌用日志真实牌山），因此每个候选只有 1 个样本。
要让它有分辨力，必须回到设计里的 **M 次采样**：

```
每个候选：M=16~32 次
  每次：从未见牌里**随机**抽我方与对手的摸牌（不再用日志牌山），
        对手用 shadow 动作但牌随机（或也换成模型），
  V(a) = mean_m [ 真实 deltas（若走到结局） 或 Q bootstrap ]
```

代价：M× 于当前（38.5 ms × 16 ≈ 0.6 s/分支）。20k 状态 × 4 候选 ≈ 13 卡时 ⇒ **8 卡约 1.7 h**，可接受。

**止损**：若 M=16 后自洽性仍 <0.55，则本条线（shadow rollout）判死，
应改用「4 席全部模型驱动」的完整自博弈 rollout（成本 ×4，但信息量完整）。

**当前状态**：S1 ✅ / S2 🔄（机制与混合终值跑通；单样本分辨率不足）/ S3 ⏳（需多采样）

## 4M 的实现（不改 Rust）

`OneVsThree::py_vs_py(challenger, champion, ...)` 原本就是一个学习者席位 + 3 个对手席位，
只要把 champion 也做成「当前策略的 engine」就是真自博弈。两处关键：

1. **权重同步**：champion engine 与 challenger **共享同一份 `(mortal, dqn)` 引用**，
   不复制模型 ⇒ trainer 每步更新权重时对手自动跟随。
2. **样本 4 倍**：两个 engine 的 `name` 都设 `'trainee'` ⇒ mjai 日志 `start_game.names`
   是 4 个 `'trainee'` ⇒ `libriichi/src/dataset/gameplay.rs::load_events` 的
   `player_names_set.contains(name)` 过滤会把**同一局的 4 个席位全部展开成样本**
   （实测每轮步数 30 → 121~2000）。

配置开关：`[train_play].champion = 'baseline' | 'self'`（默认 `baseline`，旧行为不变）。

## 为什么仍然失败

4 席同策略互打是**严格零和**：一家的收益就是另一家的损失，
每局期望 reward = 0 ⇒ **梯度的一阶信号为零，只剩方差**。

可观测的后果：
- `dqn_loss` 持续下降（0.3397 → 0.2778）、`var_q/var_t` 从 1.12/1.62/1.27 收敛到 0.78/1.19/0.88、
  `R2` 从 −1.078 升到 −0.699 —— 模型越来越**自洽**；
- 同时 holdout `top1` 单调下降（0.8198 → 0.8064）—— 但这个"自洽"的解**不是人类的策略分布**。

⇒ 结论与档 A 一致，并补上一个关键排除：**「对手是否更新」不是变量，
「数据来自自己 vs 来自人」才是**。自博弈要有效，必须叠加
① 与人类数据混合；② 强对手（akochan/搜索）；③ batch 512 —— 5 卡上 3~4 天起，
历史证据（三次尝试）均指向"不是杠杆"。

**产物**：`mortal/config.selfplay_4m{,_smoke}.toml`、`mortal/player.py`、
`logs/selfplay_4m/`（含 `holdout_compare.log`、`holdout_960k.log`）、
`mortal/checkpoints/selfplay_4m/`。

## 探索能不能救自博弈？—— 4M-expl 的答案（2026-11-08）

**动机**：4M 的失败解释是「4 席同策略严格零和 ⇒ 期望 reward = 0 ⇒ 梯度一阶信号为零」。
自然的反例是：**加大动作探索**，让数据里出现"当前策略不会选的动作"，从而得到反事实信息。
配套的第二个猜想是「改用纯 MC 回归，不压制 off-distribution 动作」。

**两个前提核实（避免做无用功）**：
1. **纯 MC 回归本来就生效**：`train.py` 的 `cql_loss = 0; if not online: cql_loss = ...`
   ⇒ online 模式下 CQL 恒为 0。M5 / 4M 一直就是纯 MC（只多了 `next_rank` 辅助头，w=0.2）。
2. **原来的"探索"名存实亡**：`boltzmann_temp = 0.1` 把 Q 放大 10 倍（Q 标准差 ≈0.61 →
   ≈6.1），softmax 几乎 one-hot。所谓 5% 探索，实际是在 5% 的时间里依然选 argmax。

⇒ 真正没测过的只有**探索强度**。臂：`eps 0.05→0.30`、`temp 0.1→1.0`，其余与 4M 完全一致。

**结果（三个独立指标都指向同一结论）**：

| 指标 | 4M（弱探索） | 4M-expl（强探索） | 变化 |
|---|---:|---:|---|
| holdout top1（3 seed 均值） | 0.8139 | **0.8137** | −0.02pp（噪声内） |
| dqn_loss（↓好） | 0.3461 | **0.2647** | **−23.5%** |
| R2（↑好） | −1.118 | **−0.620** | **+45%** |
| var_q/var_t | 1.09/1.58/1.27 | 0.68/1.03/0.77 | 明显收缩 |
| **对打 2000 局 avg_pt** | — | **+0.58 ± 2.0** | 无差异 |
| 自博弈内 avg_rank（48 局） | 2.5（对称） | **2.375** | 30% 探索不吃亏 |

**怎么读**：
- 探索**确实提供了真实信息**：dqn_loss 降 23.5% 意味着 Q 对"自博弈环境的实际回报"估得更准。
- **但 Q 更准 ≠ 策略更好**：top1 不变、对打不变 ⇒ 探索改变的是 Q 的**幅度**，不是**排序**。
- 原因：这是**无方向的随机采样**（没有 MCTS/rollout）。在 ~30 个合法动作、大量近似等价的
  麻将动作空间里，"随机抽到一个真正更好的动作"的概率极低，所以学到的只是
  "这些动作大概值多少"，不会产生新策略。
- **AlphaZero 用 MCTS 而非 ε-greedy 自博弈，正是这个道理**：搜索提供有方向的改进，
  随机探索只提供方差。

**对"能否用探索搜索更优路径"的最终回答**：
> 能提高 Q 的估值精度，但不能提高策略质量。
> 要真正搜索更优路径，必须换成**搜索**（MCTS / rollout / 策略迭代），成本比 5 卡 × 几小时高一个数量级。

## 只探索 top-5 会怎样？—— 4M-top5 的答案（2026-11-09）

**动机**：「模型已足够好，就在它自己的 top-5 候选里探索」——直觉是反事实样本集中在
质量相近的动作上，单位样本信息量更高、也不会太差。

**实现**：`engine.py` 新增 `boltzmann_top_k`：采样前先把第 k 名之后的 logits 全部掩成 `-inf`，
再走原来的 softmax / top-p 采样。臂：`epsilon 0.30→1.00`、`top_k=5`，其余与 4M-expl 完全一致。

**先测出一个关键事实**：不加任何约束时，全域 softmax 采样本来就有 **45.7%** 落在 top5 内。
所以 top-k 限定实际只影响剩下 54% 的样本——这也解释了为什么 4M-expl（eps 0.30）的改动看起来那么小。

**四条臂的剂量-反应（同一模型起点 S6c/956k，同一 4000 步）**：

| 臂 | 探索 | top1 | dqn_loss | R2 | var_q/var_t | 对打 vs S6c |
|---|---|---:|---:|---:|---:|---|
| S6c | — | **0.8198** | 0.3397 | −1.078 | **1.34** | — |
| 4M | eps .05 / temp .1，全域 | 0.8139 | 0.3461 | −1.118 | 1.31 | +1.55±2.0 |
| 4M-expl | eps .30 / temp 1.0，全域 | 0.8137 | 0.2647 | −0.620 | 0.83 | — |
| **4M-top5** | **eps 1.0 / temp 1.0，top5** | **0.8094** | **0.2147** | **−0.314** | **0.55** | +0.85±1.2（6000局） |

**三条同向单调关系，指向同一个机制**：

- 探索越集中在高 Q 区 ⇒ `dqn_loss` 越低（0.3461 → 0.2647 → **0.2147**）、R2 越好；
- 同时 ⇒ **Q 方差坍缩越严重**（1.34 → 0.83 → **0.55**，只剩目标方差的 55%）；
- 同时 ⇒ **top1 越低**（0.8139 → 0.8137 → **0.8094**）。

**机制**：Q 的回归目标只在「被采样的动作」上计算。把采样池限定在 top5 之后，top5 的 Q 被拉向
彼此相近的 MC 回报（同一状态下只差一步、后续策略相同），而 top5 之外的 Q **完全不被监督**。
⇒ 系统性丢弃 Q 的低端信息 ⇒ 方差收缩 ⇒ **argmax 区分度下降** ⇒ top1 变差。

**教训（可直接复用）**：
> 在 Q 学习里，探索不只是「要随机」，还必须**覆盖差的动作**来维持 Q 的尺度。
> 只探索好动作 = 自毁 Q 的区分度，是一剂「指标好看、能力下降」的毒药。

**一个必须记住的统计教训**：top5 vs S6c 的第一组 2000 局给出 **+3.62**，看着像 1.8σ 的边缘信号；
换两组牌山后回到 **+0.36 / −1.44**，6000 局合并只有 **+0.85 ± 1.2**。
⇒ **2,000 局的 SE≈2.0，单组 ±4 全是噪声**。任何 <3σ 的单组对打结果都不能当信号，
至少要跑 3 组不同牌山再合并。这和「holdout 必须同 seed」是同一类错误。

**最终判断**：自博弈的四个变体（4M / 4M-expl / 4M-top5 / 假自博弈 M5）在**强度上全部等价于起点**
（+0.85 ~ +1.55，全部 <1σ）。它们之间唯一的差别是「把 dqn_loss 压得多低、把 Q 方差压得多小」，
而这个方向与能力**无关甚至相反**。

## baseline 降方差 + 代际对手池：能不能救？—— 答案仍是不能（2026-11-09）

**两个变量分开测**：

### 变量 1：baseline V(s) 降方差（唯一无副作用的改进）

实现：`control.baseline_v_weight > 0` 时起一个 `VHead`（262k 参数），把 Q 的回归目标改成**优势**：

```
A(s,a) = q_target_mc − V(s).detach()      # V 另用 0.5·MSE(V, q_target_mc) 监督
```

因为 `V(s)` 与动作无关 ⇒ `argmax_a A ≡ argmax_a Q`，**策略语义完全不变**，只是把"这个状态本身值多少"
从回归目标里减掉，梯度方差大幅下降。`v.detach()` 不能省，否则 V 会学成"让 Q 误差最小"。

| 臂 | top1（3 seed） | 相对上一代 |
|---|---:|---:|
| 4M-top5（无 baseline） | 0.8094 | — |
| **A：top5 + baseline** | **0.8125** | **+0.31pp（3/3 seed 全升）** |
| S6c（起点） | 0.8198 | 仍未回到 |

⇒ **baseline 确实修了"Q 方差坍缩 ⇒ argmax 不稳"这一环**，是这一整条线里唯一有没有副作用的改动。
但它只能"止损"，不能凭空造出更优策略。

### 变量 2：代际对手池（`champion='pool'`）

实现：`champion_pool = [B/756k, S6c/956k, 4M-top5/960k]`，每轮 `random.choice` 抽一个占 3 个对手席位。

**第一次尝试直接坍塌**（eps 仍是 1.0）：

```
自博弈内 620 局：avg_rank 3.323、avg_pt −69.10、拿第 1 名的轮次占比 0.0%
test_play：agari 4.88% / houjuu 20.60% / fuuro 60.40% / riichi 5.70%、avg_rank 3.585
```

**根因（重要机制）**：challenger 是 **100% top5 采样**，而池里的对手全是 **greedy**。
行为策略必然弱于对手 ⇒ 一步都赢不了 ⇒ Q 学到"我怎么做都输" ⇒ 正反馈坍塌。
4M-top5 同样 eps=1.0 却不崩，因为对手是**同一份权重的 greedy 版本**（除探索噪声外同源）。

> **规则：探索率只能在"自己打自己"时放大。一旦对手是外部固定模型，必须降回 ε ≤ 0.1。**

**降到 eps=0.10 后恢复正常**（B2 臂，492 局 avg_rank 2.502 / avg_pt +0.82），但：

| 指标 | A（无池） | **B2（有池）** | 变化 |
|---|---:|---:|---|
| holdout top1 | 0.8125 | **0.7998** | **−1.27pp** |
| fuuro（人类 32.63%） | 29.04% | **33.00%** | 更像人 |
| riichi（人类 18.25%） | 18.90% | **17.32%** | 更像人 |
| 强度 vs S6c | — | **+0.26 ± 1.42**（4000 局） | 无差异 |
| 强度 vs A | — | **+0.25 ± 1.42**（4000 局） | 无差异 |

⇒ **代际池让宏观行为最像人类，但 top1 再降 1.27pp，强度依然无增益。**
推测：面对强对手被迫更谨慎（多副露、少立直），但学到的是"对抗这批特定对手的价值"，不是人类场的价值。

### 七个变体的总账

| 臂 | 探索 | 对手 | 额外机制 | top1 | 强度 vs S6c |
|---|---|---|---|---:|---|
| **S6c（起点）** | — | — | — | **0.8198** | — |
| 4M | eps .05 / temp .1 | 自己 | — | 0.8139 | +1.55±2.0 |
| 4M-expl | eps .30 / temp 1.0 | 自己 | — | 0.8137 | +0.58±2.0（vs 4M） |
| 4M-top5 | eps 1.0 / top5 | 自己 | — | 0.8094 | +0.85±1.2（6000 局） |
| **A** | eps 1.0 / top5 | 自己 | **baseline V(s)** | 0.8125 | — |
| **B2** | eps 0.10 / top5 | **代际池** | baseline V(s) | 0.7998 | +0.26±1.42 |
| **C** | eps 1.0 / top5 | 自己 | baseline + **CQL** | **0.8160** | **−0.37±1.42** |

**top1 在 0.7998~0.8198 之间波动，与强度完全无相关**（最好与最差变体的强度都落在 ±1.5 内）。

### 结论

1. **baseline 是这条线唯一的真改进**（修 Q 尺度、无副作用），值得保留为基础设施；`cql_online` 是第二个（维持 Q 区分度）——两者都应该在今后任何 Q 学习训练里默认打开；
2. **代际对手池是负收益**（top1 −1.27pp、强度不变），不建议继续；且它与高探索率**不兼容**（eps 1.0 + 外部 greedy 对手 ⇒ 620 局 0% 第 1 名、正反馈坍塌）；
3. **CQL 能把指标修回正确方向**：`gap` 1.034→**1.570（+52%）**、信噪比 1.49→**2.04**、top1 回到 0.8160（距起点 0.38pp），**但强度仍 −0.37±1.42** ⇒ **瓶颈不在 Q 的精度或区分度**；
4. **自博弈的障碍不是规模，是信号**：单次回报噪声 SD≈0.59 > 多数动作之间的真实价值差，所以「七个变体 × 各种采样/损失/对手」都学不出方向；
5. 若还要走，只剩 **状态级 rollout 估值**（需给 `BatchGame` 加「从中间状态继续」，约半天 Rust）；但按第 4 条，需先算「rollout 方差能否压到 0.59 以下」，否则不做。

# 设计：全知数据下的「铳牌动作损失」与押し引き平衡（2026-10-29）

## 0. 目标

用**全知数据**（四家真实手牌 + 听牌）计算「有人听牌时，手里每张牌的铳牌动作损失」，
降低模型放铳率，但**不能变成轻易弃牌**：

> 只有当「弃牌（只打安牌）的期望收益 > 继续做牌对攻的期望收益」时才弃牌。

## 1. 已完成的测量（`tools/oracle_deal_loss.py`，120 局 / 202609）

用 4 个 `PlayerState` 同步重放，取对手**真实听牌** `waits_j`（34 维布尔）：

```
danger[a] = |{ j : a ∈ waits_j }|
loss[a]   = danger[a] × 3000 点     （先按每家 3000 粗算，立直应改 5200）
```

| 指标 | 数值 |
|---|---|
| 我方打牌决策 | **15,085** |
| 其中「至少一家听牌」 | **5,177（34.3%）** |
| 人类：打安全牌 / 打危险牌 | **96.6% / 3.4%** |
| 期望失点（有人听牌的状态上） | 人类 **103 点/decision**；最安全 **0** |
| 打危险牌时「其实有安全牌可打」的比例 | **100%** |

⇒ **基线很清楚**：人类在有人听牌时几乎不冒险（3.4%），一旦冒险必然有安牌可打，
平均每次状态付出 103 点（≈0.034×3000）。

## 2. 押し引き判据（平衡点）

在同一单位（点数）上比较两条路：

```
继续对攻：EV_push = max_a [ atk(a) − def(a) ]      # def(a) = P(deal|a)·loss
弃牌扎安：EV_fold = max_{a: def(a)=0} atk(a)        # 安全牌里攻击力最高的一张
```

- `atk(a)`：v4 obs 的 SP 表（`ev_norm × max_ev`，单位点）——精确 DP，已内置；
- `def(a)`：离线用**全知** `waits_j`（P(deal|a) ∈ {0,1}），线上用 A2c 后验近似；
- 决策：`argmax_a [atk(a) − def(a)]`（等价于「只有对攻收益盖过铳损才推」）。

**为什么不直接按人类 3.4% 的弃牌率对齐**：那是「模仿一个比率」，会把人类的过度保守也学进去；
用**价值比较**才能得到「该推就推、该弃就弃」。

## 3. 训练信号（三选一，按侵入性排序）

| 方案 | 做法 | 侵入性 | 预期 |
|---|---|---|---|
| **T1 样本加权** | 在「有人听牌」样本上，对 `loss(a_human) > 0` 的样本降权（或对安全选择升权），权重 `w = 1/(1+loss/3000)` | 低（只改 dataloader） | 降放铳率，但不改变决策边界 |
| **T2 定向难例** | 只对「模型选了危险牌、而全知显示有安全牌」的状态做额外 BC 步（类似 hard-example mining） | 中（新采样器） | 直接压低最危险的 3% 决策 |
| **T3 teacher 蒸馏** | 用 `argmax[atk−def]` 生成软标签，替代这 34% 状态的人类标签 | 中高（新 teacher） | 真正改变边界，但要用 16k 臂验证 |

**建议顺序**：T1（半天，验证方向）→ T3（若 T1 有正效应）。

## 4. 验收

1. **离线**：在 5,177 个「有人听牌」状态上，模型的「打危险牌率」应从当前值降到 ≤3.4%，
   且「有安牌不打」的比例显著下降；
2. **平衡性**：模型的**弃牌率不能暴涨**（否则进攻端崩），必须同时看 `agari`（和了率）；
3. **在线**：16k sets 标准臂（δ_min≈0.43），种子 **600000/620000**；同时看 holdout 放铳率。

|---|---|---|

判据：

```

弃牌扎安：max_{a: def(a)=0} atk(a)

下一步：在这 3.2% 的对攻样本上算 `EV_push − EV_fold` 的分布——
若大部分为负，说明**人类在过度对攻**，模型可以靠"更会弃"赢；若为正，则这条线彻底关闭。

## 8. EV_push − EV_fold 首跑（2026-10-29）：**口径未接通（Δ 全 0）**

`tools/oracle_push_fold.py --games 100 --model`：

```
[push] 我方决策 12,629；有人听牌 4,369
[全部有人听牌]: n=4369  中位 Δ=+0  Δ>0 0.000  Δ<0 0.000
[人类推了对攻]: n=144    —— 该推 0 / 该弃 0
[模型推了对攻]: n=134    —— 该推 0 / 该弃 0
```

**Δ 恒等于 0 ⇒ `atk(a)`（SP 项）全为 0**，不是「人类恰好都对」。

可能原因（按概率排序）：
1. `ev_rerank.sp_features()` 对 `encode_obs` 产出的 obs **不认为被覆盖**（`covered=False`），
   于是 `ev_norm` 返回全 0；档 B 的 `ei_teacher.py` 用的是 read-model harness 的 obs，那里是有效的；
2. `max_ev` 在该状态下为 0（未听牌/无有效进张时的默认值），乘出来也是 0；
3. 行号假设（SP 表在 961..1011）与 `encode_obs` 的实际布局不一致。

**排查方法**：对同一局同一步，分别用
(a) `sts[0].encode_obs(4, False)` 与 (b) `GameplayLoader` 的 obs，比较 `sp_features` 的
`covered / max_ev / ev_norm.sum()`，即可定位是布局问题还是覆盖问题。

在修好之前，**Δ 的分布没有结论**；人类的 3.2% 对攻是否值得，仍未知。

## 9. Δ 全 0 的排查结论（2026-10-29）：**不是 `encode_obs` 的问题**，是 `atk` 项

### 9.1 已排除：`encode_obs` 与 GameplayLoader 的 obs **完全一致**

同局同一步的对比（`tools` 内联诊断）：

| 来源 | cand_sum | SP 表总和 | covered | max_ev | ev_norm.sum |
|---|---|---|---|---|---|
| `sts[0].encode_obs(4, False)` | 13.0 | 42.6287 | **5** | **877.0** | 4.690 |
| `GameplayLoader` | 13.0 | 42.6287 | **5** | **877.0** | 4.690 |

⇒ 逐位相同，**obs 布局没有问题**；§8 的第 1、3 条假设被否证。

### 9.2 已排除：「没有危险牌」导致两边相等

```
有人听牌状态 659，其中「手里有危险牌」410（0.622）
```

⇒ 62.2% 的状态手里确实有危险牌，`defv[own] > 0` 应当成立，
`EV_push` 与 `EV_fold` 不可能在全部样本上恰好相等。

### 9.3 结论：**`atk(a) = ev_norm × max_ev` 在多数牌上是 0**

`ev_norm` 只在 `covered` 的候选牌上非零（本例 13 个候选里只有 **5** 个被覆盖），
其余为 0；若「被覆盖的候选」与「自家手牌里攻击力最高的那张」不重合，
`atk` 的最优点会退化到 0，于是 `EV_push ≈ EV_fold ≈ 0` ⇒ Δ ≡ 0。

**修法（下一步）**：
1. 用 `sp['covered']` 做掩码，**只在 covered 的自家牌之间比较**；
   若 covered ∩ own 为空，则该状态记为 `atk_unknown` 并单独统计，而不是当成 0；
2. 或改用「未覆盖时退化为 `p_win`/进张数」的替代攻击项；
3. 修好后重跑，才能得到 Δ 的真实分布。

### 9.4 当前可确认的事实（不受此 bug 影响）

| 事实 | 数值 | 来源 |
|---|---|---|
| 模型在有人听牌时的弃牌率 | 96.9%（人类 96.8%） | §7 |
| 模型期望失点 | 118 点（人类 120） | §7 |
| 有人听牌且手里有危险牌 | 62.2% | 本节 |

⇒ 「模型放铳不比人类多」这点是**确定的**；「人类的 3.2% 对攻是否值得」仍**未回答**。

```

[全部有人听牌]: n=4072  Δ>0 0.000  Δ<0 0.000
[人类推了对攻]: n=90   该推 0 / 该弃 0

```

### 10.3 唯一还成立的解释：**`ev_norm` 在 34 张牌上恒定**

若 `atk(a) = ev_norm(a) × max_ev` 对所有 a 相同（记作 c）：
`EV_push = c − min(def)`，`EV_fold = c` ⇒ **只要有一张安全牌（def=0），Δ 恒等于 0**。
现在 4072 个样本全部 Δ=0，且「无安牌可弃」只有 56 个，
⇒ **`ev_norm` 逐牌相同**，SP 表在我们取到的那一刻是**按行广播**的（不携带逐牌信息）。

### 10.4 下一步（二选一）

1. **验证**：打印同一状态下 `evr[own]` 的 min/max/std。若 std=0 ⇒ 确认是广播，
   应改用**真正逐牌的攻击量**：`p_win`（和了概率，逐牌）或「进张数变化 / 向听」
   （`shanten` + `unseen` 可算）；
2. **换口径**：攻击项不用 SP，改用 `p_win(a) × 平均打点`（v4 obs 的 win 表也是逐牌的，
   但要先确认它同样不是广播）。

**结论**：`def(a)`（全知铳损）这一半已经完全可靠（4 席 `waits` + 立直/默听/副露权重）；
缺的是**逐牌可比的攻击项**。在补上之前，`EV_push − EV_fold` 的分布仍无法回答
「人类的 3.2% 对攻是否值得」。

## 1. 权重设计

对每条牌谱只读首行 `start_game.names`，取 4 名玩家的长期 `avg_pt`
（`dataset/index/player_ratings_2022_2026H1_v3.csv`，要求每人 ≥100 局），

```
quality = min(avg_pt of 4 seats)
```

按 quality 分位切档，映射为整数重复次数（所有文件至少 1 次，不做过滤）：

| 档位 | 重复 | 文件数 | 样本占比 |
|---|---|---|---|
| `min_pt < −0.765`（底部 75%） | ×1 | 369,428 | 55.5% |
| `−0.765 ~ +0.374`（75–90 分位） | ×2 | 74,089 | 22.3% |
| `> +0.374`（前 10%） | ×3 | 49,293 | 22.2% |

- 切点 `[0.5, 0.75, 0.9]`、重复 `[1,1,2,3]`；前两档重复相同 ⇒ **q50 切点惰性**，
  实际生效的是「底部 75% 原样、前 25% 加权」。
- 均值 **1.350**，文件表 492,810 → **665,485** 条；492,798/492,810 局可评分
  （4/4 评分 461,254；3/4 30,709；2/4 835；1/4 12）。
- 为什么用 `min` 而不是均值：4 人 avg_pt 接近零和，均值几乎恒为 0（sd 1.9），
  最弱一席的分布 sd 5.0，信息量最大。

```

- `Brain(is_oracle=True)` 已存在（`model.py` 的 `torch.cat((obs, invisible_obs), 1)`），
  本实现只补 **α 调度、数据管线、推理零填充** 三块。
- α 以**本次暖启后的步数**为 0 点（父代 956k → `og_start_step`），否则 α 会永远钉在 0。
- 续训安全：`oracle_start_step` 写进 checkpoint，重启从断点继续调度，不会把 α 拉回 1.0。

|---:|---:|---:|---:|---:|---:|

| 980k | 0.80 | 0.8149 | −0.18pp | 0.3715 | +2.8% |

**判定：FAIL**——终点 top1 −0.49pp，超出 −0.3pp 容差（dqn_loss 那一半通过）。

两条解读：

1. **不是崩溃式捷径**：退火期间 top1 只掉 0.2~0.4pp、loss 只升 ~3%，α=0 后
   1,040k 还回升到 −0.09pp；终点 −0.49pp 里含噪声。5 个点的均值 ≈ **−0.28pp**，
   恰好压在容差线上。
2. **但行为确实变了**（1,050k 的 test_play，800 局，vs 200k 基线）：
   和了 **21.63%**、放铳 **9.83%**、副露 **27.57%**、立直 **18.40%**；
   对照 S6c/956k：21.67% / **12.27%** / **31.09%** / 18.55%。
   ⇒ 和了持平、**放铳 −2.4pp、副露 −3.5pp**：策略明显转向防守。
   这与“Q 拟合更好（loss −2.3%）但人类动作一致性下降（top1 −0.49pp）”完全一致：
   oracle 没有提供新的可学信号，但把 Q 的景观推向了更保守的一侧。

**按预注册：停在这里，不上 16k 臂。** 若 PI 愿意破例检验“更保守是否更强”，
可用 1,040k 快照（α=0 后 top1 最好，−0.09pp）跑 16k 臂；但这属于协议例外，
需要在 MEMORY §3 记录并接受多重比较的代价。

## 6. 风险与边界

- **捷径风险**：模型可能把 oracle 当捷径，α=0 后崩塌；探针要看 α=0 的 holdout 曲线，
  而不只是训练 loss。Suphx 用长退火缓解，本实现给了 50k 步退火。
- **信息上限**：本仓库"全知铳损"探针显示给了全知信息后弃牌已与人类持平
  （96.9% vs 96.8%）⇒ Oracle Guiding 更可能改善**学习效率**，而不是抬高天花板。
- **只支持 `cql_mc`**：IQL 需要 `next_invisible_obs`，dataloader 未提供；已加断言。
- **部署兼容**：旧 ckpt（`is_oracle` 缺失）行为逐位不变；oracle ckpt 走
  `engine` 零填充，`ladder`/`one_vs_three`/`test_play` 均已适配。
