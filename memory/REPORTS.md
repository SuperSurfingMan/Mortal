## 7. 追加诊断（2026-10-28 晚）：残差到底是「歧义」还是「分歧」

**先否证一条方法论**：精确重复匹配不可行 —— 76 万打牌决策里**同状态重复组 = 0**；
换成粗键（手牌+轮目+可打牌掩码）也只有 **0.11%** 覆盖（431 组、862 样本），且粗键会
混淆不同「已见牌」的同一手牌 ⇒ **无法用重复组直接估人类噪声地板**。

改用三个可观测替代量（`tools/label_noise_diag.py`，S6c/956k，60,000 打牌决策）：

| 指标 | 值 |
|---|---|
| top1 | 0.7468（202512 训练池内同口径 0.7496 ⇒ 无过拟合，与 holdout 结论一致） |
| **top3 / top5** | **0.9506 / 0.9750** |
| 错误处的 `Q(top1) − Q(human)` | 中位 **+0.722**、p75 +1.475、p90 +2.481 |
| 错误中 \|差距\| ≤ 0.05 / 0.1 / 0.25 / 0.5 的占比 | **4.6% / 8.7% / 21.1% / 38.7%** |
| 按「top1−次优」五分位的准确率 | 0.443 / 0.611 / 0.776 / 0.916 / **0.988** |

**结论（关键）**：残差**不是**「多个合理动作的歧义」——只有 4.6% 的错误落在 0.05 的
近似平局内，中位差距 **0.72**（与该模型典型 Q 边际 1~5 相比是实打实的分歧）。
人类动作有 95% 落在模型 top-3 内，说明模型「看得见」人类的选法，但**更偏好别的**。

推论：
1. **继续追 BC 一致率（top1）价值有限** —— 剩下的错误是模型有主见的不同判断，
   而不是标签噪声；提高一致率最多是把模型拉向人类的平均倾向。
2. 强度提升更可能来自 **有评估能力的改法**：搜索/专家迭代（B2）、或引入能改变这些
   判断的新信息（A1 对手建模辅助任务、A2 风格/对手条件）。
3. 同时也解释了为什么 S6c 只值 +0.42 而不是更多：它改变的是「局部选牌倾向」，
   而那些高置信分歧不是靠再加两行特征能翻转的。

⚠️ 口径说明：本工具在同一数据上给 0.747（202609）/0.750（202512），而 `holdout_metrics`
给 0.8167 —— 两者**采样与过滤口径不同**（本工具取每局全部打牌决策，不排除单位置可打牌
的退化状态）。**绝对值不可与 holdout 直接比，结构结论（top3/top5、错误差距分布、
分层准确率）不受影响。**

**这一阶段的净结论（三条）**

1. **绝对强度已测定**：+0.00 ± 1.68，即「凤凰场常客平均水平」，不是「强」（p95）。过去 6 周所有单点改动的最好成绩是 +0.42（S6c），仅为目标差距（5.4 pt）的 8%。
2. **指标 ≠ 强度**：守卫 / Oracle Guiding / 探索 / CQL / baseline / 代际池，全部能改变 top1、dqn_loss、gap、行为画像中的一项或多项，但**强度一律等于起点**。机制统一：它们都只是沿「放铳↔速度」或「拟合↔泛化」的同一 frontier 移动。**2026-11-14 的更硬证据**：官方 Mortal 4.1c 的人类一致率比自家 2023 年的 v3 低 **2.55pp（显著）**——一个更新的模型，在这个指标上反而更像外行 ⇒ **一致率衡量拟人度，与强度反向**（MEMORY §3.22b）。
3. **自博弈的障碍不是规模，是信号**：单次回报噪声 **SD≈0.59**，大于多数动作之间的真实价值差（top1−top2 中位 0.6~2.2 但仍含噪声）；七个变体在增加探索、修正损失、更换对手后都学不出方向。

# 行为画像口径统一（2026-11-07）

## 0. 一句话

用 `libriichi/src/stat.rs` 的**同一定义**重算人类凤凰场，得到 **副露局占比 32.63%**，
而 Mortal(S6c) 是 **31.09%** —— 只差 **−1.54pp**。
「Mortal 副露只有人类 2/3、太保守」这个贯穿了 6 周的诊断，**基于错误的 48.26% 基准，不成立**。

## 1. 为什么要做

仓库里"副露率"出现过三个互不一致的数：

| 来源 | 值 | 实际含义 |
|---|---:|---|
| MEMORY §2.5（B/756k 行为对照） | **45.66%** | 未文档化；与本次实测不符 |
| MEMORY §3.15（年度审计） | **5.277 次/半庄** | 副露**次数**，÷8 局 = 0.66 次/局 |
| MEMORY §3.11（S6c 训练期画像） | **31.09%** | `riichi.Stat` 的 `fuuro_rate` |

同一个指标差出 14~15 个百分点，而"模型太保守"这个结论正是靠第三行 vs 第一行比出来的。
**在修尺子之前，任何"改善行为"的改动都缺一个可信的靶子。**

## 2. 口径（唯一真源 `libriichi/src/stat.rs`）

```rust
Event::StartKyoku        => stat.round  += 1;              // 每人每局 +1
Event::Hora { actor }    => stat.agari  += 1;              // 自摸/荣和都算
                            stat.houjuu += 1 (target≠actor) // 放铳记在 target
Event::Reach  { actor }  => stat.riichi += 1;              // 一局最多 1 次
Event::Chi | Pon | Daiminkan if actor == me => fuuro_num += 1;
Event::EndKyoku          => if fuuro_num > 0 { stat.fuuro += 1 }  // **每局最多 +1**
Event::Ryukyoku          => stat.ryukyoku += 1 (4 人各 +1)
率 = 分子 / round
```

⚠️ 两个易错点：
1. **`fuuro_rate` 是「有副露的局占比」（≤1），不是「副露次数/局」**；
2. **副露只算 `chi/pon/daiminkan`，不含 `ankan/kakan`**。

## 3. 实测（`tools/behavior_profile.py`）

- 人类侧：`dataset/mjai/houou4/202[2-5]??/**/*.json.gz`（训练池主体），随机 3,000 文件
- 解析：JSONL 逐行事件（不是 JSON 数组），**126,288 人·局**
- Mortal 侧：直接读 `riichi.Stat` 的输出（`train.py` 的 `behavior:` 行、`ladder.py` 的 `run_meta.json`），**同源，无需重跑**

| 口径 | 和了率 | 放铳率 | **副露局占比** | 立直率 | 流局率 |
|---|---:|---:|---:|---:|---:|
| **人类凤凰场（实测）** | **21.14%** | **12.65%** | **32.63%** | **18.25%** | **16.00%** |
| S6c/956k | 21.67% | 12.27% | 31.09% | 18.55% | — |
| B/756k | 21.92% | 12.86% | 28.26% | 20.05% | — |
| **差距（S6c − 人类）** | **+0.53pp** | **−0.38pp** | **−1.54pp** | **+0.30pp** | — |
| 差距（B − 人类） | +0.78pp | +0.21pp | **−4.37pp** | +1.80pp | — |

自洽性检查：32.63% 的局有副露、0.66 次/局 ⇒ 有副露的局平均 **2.02 次**（吃完还能再碰），合理。

## 4. 三条结论

1. **S6c 的行为画像与人类凤凰场几乎完全对齐**：四项里三项在 ±0.6pp 内，唯一超过 1pp 的是副露 **−1.54pp**（仍 <3pp 容差）。
2. **"弃和不足 / 太保守"的诊断被推翻**：那是拿 S6c 的 31.09% 去比一个不同口径的 48.26%。
   按同口径，S6c 的副露只比人类少 1.5pp——**远小于 ladder 的 ±0.66 分辨率所能支撑的"可改善空间"**。
3. **B/756k 的副露 −4.37pp 才是真实偏离**，而 S6c（+速度特征）把它修到 −1.54pp。
   也就是说 **S6c 已经顺手修掉了这个缺口**，不需要再单独做"加副露"的改动。

## 5. 对路线的影响

| 旧判断 | 新判断 |
|---|---|
| "副露 31% vs 人类 48%，模型太保守" | **伪**（人类同口径 32.63%，差 1.54pp） |
| "下一步增益应提高和了效率/打点" | 和了率已 **+0.53pp**（高于人类），**没有提升空间** |
| "守卫/OG 让模型更保守所以可能更强" | 没有"过度进攻"可修，保守化只是偏离对齐点 |
| 行为侧还有 +3pp 级的可调空间 | **没有**（四项全部 ≤1.54pp） |

**这解释了为什么守卫（λ 重扫）、OG 的 α 退火、B 的"更保守"全都没有收益**：
模型的行为已经在人类分布上，任何"往某个方向推"的改动都是在**离开**最优点。

## 6. 唯一待核实的残留

`流局率`：人类 **16.00%**，Mortal 侧**无数据**（`ladder.py` 的 `run_meta.json` 只写 4 个率，
`train.py` 的 `behavior:` 行也不含 `ryukyoku_rate`）。

MEMORY §2.5 曾记"Mortal 流局 10.9% vs 人类 15.3%"，若同口径成立则是 **−5.1pp** 的真实缺口。
但：**和了 +0.53pp 与放铳 −0.38pp 已经解释了绝大部分"局如何结束"**（两者合计 33.94% vs 人类 33.79%），
流局率若真的差 5pp，剩下的 5pp 必须落在"其他结束方式"（杠流局/九种九牌/切牌流局）上——
这更像是**统计口径差异**而非行为差异。

**建议**：下次跑 ladder 时把 `ryukyoku_rate` 一并写进 `run_meta.json`（一行改动），
就能彻底关闭这个问题；当前不为此单独烧卡。

# AI similarity：S6c vs v3-ref vs 官方 4.1c（2026-11-13；2026-11-14 补官方同局对照）

## 0. 一句话

在同一批人类凤凰场牌谱上，三个模型的人类一致率（**口径 B**：`mask>=2`，与官方 reviewer 的决策点**逐局完全相同**）：

③ **「AI 一致率」衡量拟人度，不衡量强度，且方向与强度相反** —— 不能拿它给模型排名。

⚠️ **两个边界（都不能省略）**：
1. **v3-ref 不是官方发布**（详见 §2.1）：个人账号 `hhim8826` 上传、经第三方重新打包的权重，
   官方自 2022-08-19 起明确不公开权重。若它是某人自训的 v3，则本报告证明的是「这套方法的收敛点」，而不是「复现了官方」。
2. 4.1c 的对照（§3.2）混合了「代次 v3→4.1c」与「实现：官方 reviewer vs 本仓库」两个变量；
   它能定方向，不能精确归因。

## 1. 为什么做这个诊断

社区模型卡（`VoidShine/mortal-298k`）报 "AI similarity 83%–92% on mjai.ekyu.moe"。
查证其口径：`mjai.ekyu.moe` 的分析报告「元数据」页自带「与 Mortal 的一致率」，
作者是把自家模型的牌谱提交到官方在线服务、读该字段得到的；**官方从不公开权重**。

本项目此前只有「相对人类」的指标（top1 0.8198）与「相对 akochan」的绝对锚点（+0.00±1.68），
从未测过「相对官方 Mortal」。本诊断补上这一坐标。

## 2. 方法（比社区口径更严格）

| 项 | 社区做法 | 本报告 |
|---|---|---|
| 参照系 | 官方在线服务（mjai.ekyu.moe，需 Turnstile，批处理受限） | 社区分发的 v3 权重 **`hhim8826/mortal3-b40c192`**（HF，AGPL-3.0）：v3 / 192ch / 40blocks / 10.77M 参数 / 2023-03-25。**来源未经官方确认，见 §2.1** |
| 比较对象 | 自家模型的**对局牌谱**（局面分布是自博弈分布） | **同一批人类 holdout 的决策点**（分布=人类实战） |
| 对齐 | 服务端逐手比对 | **逐文件配对**：同一个 `.json.gz` 分别用 `version=3` 与 `version=4 + s6c` 解码，逐位校验 `actions/masks` 相同后才比 argmax |

为什么不能"两个 DataLoader 并行跑"：`FileDatasetsIter` 的 `file_list`/`buffer` 都用
`random.shuffle`，且 v3/v4 的 obs 编码走不同分支（不是子集关系），跨文件会漂移
（实测第 18 批错位）。故改为**逐文件**配对，并在 `dataloader.py` 加了可选 `seed=`
（缺省 `None` = 旧行为不变）。

## 2.1 参照权重到底是谁的（重要限制）

`hhim8826/mortal3-b40c192` 是**个人账号**发布，不是 Equim 官方发布。核查结果：

**结论**：它是「**v3 架构、2023-03 训练、经第三方重新打包**」的权重，

| S6c（本仓库，v4+s6c） | 6281 / 7791 | **80.619%** | −0.36pp [−0.86, +0.18] |
| **4.1c（官方现役）** | 6110 / 7791 | **78.424%** | **−2.55pp [−3.46, −1.57]** |

- 4.1c − S6c = **−2.20pp [−3.08, −1.33]**；12 局里 **11 局**是 S6c 更高（唯一例外 idx=4，官方 +1.08pp）。
- S6c − v3-ref 的 CI 跨 0 ⇒ **不可区分**，与 §3 的 79,098 点结论（Δ +0.03pp）独立吻合。

**为什么 4.1c 反而更低**：它是「争一型」，为名次做 RL 调优，会主动偏离人类打法。
站点自己的下拉框就把最像人的网络标成 **「3.0」（更像人类，但是最弱）**——
**官方把这条反向关系直接写在界面上**。所以这不是「我们诡异」，而是这个指标的固有方向。

**副产品（口径事实）**：采集时第一份报告用了站点默认（4.1b + τ=0.10），给出 `124/161`；
正式报告（4.1c + τ=1.00）也是 `124/161` ⇒ 实测确认 **τ 不影响一致率**（只影响展示概率）。

## 4. 结论与解读修正

1. **我们与 v3 系等价（第二次独立复现）**：12 局 / 7,791 点上 S6c 80.62% vs v3-ref 80.98%，
   Δ −0.36pp、CI[−0.86,+0.18]；与 §3 的 60 文件 / 79,098 点（Δ +0.03pp）方向一致。**不是训坏了。**
2. **「AI 一致率」不能用于给模型排名**：官方 4.1c 比自家 2023 年的 v3 低 **2.55pp（显著）**，比我们低 **2.20pp**。
   该指标衡量**拟人度**，而 RL / 自博弈调优会主动偏离人类打法 ⇒ **越强的模型可能越不像人**。
   站点把最拟人的网络标为「更像人类，但是最弱」，已直接确认这一点。
3. **top1 / 一致率不能当进步门禁**：只可用于「有没有训坏」（坍塌、发散、行为画像崩坏）。
4. **92.1% 的 argmax 一致率**落在社区模型卡报的 83%~92% 上沿；考虑到我们用的是「人类局面 + 严格逐文件配对」，
   比「自博弈牌谱 + 在线服务」更苛刻，这个数值符合预期。
5. **代差已补完**：v3(2023-03) → 4.1c 这一段的参照系现在拿到了。若将来要评估「是否达到官方现役水平」，
   必须用 ladder / anchor 这类强度指标，**不能**再用一致率。

### 0.1 顺手验证了 τ 的语义

## 2. 六条新发现

### 2.1 两个模型的「价值观」高度一致，但尺度差 4 倍

| 量 | 4.1c | S6c | 关系 |
|---|---:|---:|---|
| 打牌 Q 的 Spearman ρ（逐决策点） | — | — | 均值 **0.802**、中位 **0.846**、p10 0.595 / p90 0.951 |
| ρ > 0.5 的占比 | — | — | **94.21%**（ρ < 0 仅 0.24%） |
| `gap = top1−top2` 中位 | **0.399** | **1.627** | **4.1 倍** |
| gap 的 Pearson 相关 | — | — | **0.798** |
| 全候选跨度（max−min）中位 | **1.517** | — | p10 0.583 / p90 1.991 |
| top1 的 Q 中位 | **−0.071** | — | p10 −0.275 / p90 0.345 |

**读法**：Q 的**排序**几乎一样（ρ 0.85），但**幅度**差 4 倍。
做任何蒸馏/回归前必须先做仿射对齐，否则学到的全是尺度差。

### 2.2 argmax 只在 86.4% 上一致——差值全在「近似等价」的动作上

| 人类动作类型 | 点数 | 两模型 argmax 完全一致 |
|---|---:|---:|
| 打牌 | 5,990 | **83.96%** |
| 跳过/不鸣 | 1,292 | 96.21% |
| 碰 | 155 | 89.68% |
| 立直 | 117 | 85.47% |
| 吃 | 111 | 86.49% |
| 杠 | 13 | 84.62% |
| 和/自摸 | 112 | 100% |
| **合计** | **7,791** | **86.40%** |

**结合 2.1**：ρ=0.85 但 argmax 只 84% ⇒ 分歧的那些点，两边的 top1「价值」几乎相等。
这不是「打错了」，是**在平坦区域里选了点**。

### 2.3 4.1c 分歧的地方，有 2/3 我们也分歧（「AI 共识」）

| 拆分 | 点数 | 占 4.1c 分歧 |
|---|---:|---:|
| 4.1c 分歧总计 | 1,681 | 100% |
| ├─ **S6c 与人类一致**（4.1c 孤立） | 527 | 31.35% |
| └─ **S6c 也与人类分歧**（AI 共识） | **1,154** | **68.65%** |

反向：S6c 分歧 1,531 点中，4.1c 与人类一致的只有 377（24.6%）。

而两组的**把握**截然不同：

| 组 | 4.1c gap 中位 | 人类动作类型（前二） |
|---|---:|---|
| 4.1c 孤立（n=527） | **0.107**（几乎纯随机） | 打牌 88.0% / 跳过 8.3% |
| AI 共识（n=1,154） | **0.213** | 打牌 93.6% / 吃 2.5% |

⇒ **4.1c 最「有主见」的地方，我们和它站在一起；它孤立的地方，它自己也没把握。**

「AI 共识」组里，两个 AI 选**同一张牌**的比例只有 **58.9%** ——
即"都反对人类"但方式不同，说明这是**一片平坦区域**，不是同一个明确答案。

### 2.4 两个模型对「这手难不难」的判断完全同步

按 4.1c 的 gap 四分位分桶：

| 4.1c gap | 点数 | 4.1c 分歧率 | S6c 一致率 | **S6c 的 gap 中位** |
|---|---:|---:|---:|---:|
| [0.000, 0.163) | 1,497 | **50.50%** | **57.78%** | **0.664** |
| [0.164, 0.401) | 1,497 | 33.47% | 68.27% | 1.068 |
| [0.401, 0.828) | 1,497 | 16.23% | 82.97% | 2.034 |
| [0.829, 1.915) | 1,498 | **2.87%** | **96.20%** | **4.606** |

**两列同时单调、且几乎同步**：4.1c 越确定，S6c 也越确定、越像人。
⇒ 两个模型（不同代次、不同训练目标、不同 Q 尺度）对**局面难度的排序几乎一致**。
这是"这批数据本身有难易结构"的直接证据，不是某个模型的偏差。

## 3. 对「能不能蒸馏 4.1c」的判断：价值比想象低

把上面几条拼起来：

| 前提 | 数据 |
|---|---|
| 教师与学生的 Q 排序相关 | **0.846**（已高度重合） |
| argmax 分歧 | 13.6%（1,060 点） |
| 分歧中「学生也反对人类」 | **68.65%** ⇒ 这些点学生**本来就这么想**，蒸馏不改变策略 |
| 分歧中「教师独有」 | 31.35%（527 点），**其 gap 中位仅 0.107** ⇒ 教师自己也没把握 |
| 可用样本量 | 7,791 点 ≈ 一次训练看到的 **0.008%**（9,200 万） |

⇒ **即使把 Q 全部拿来蒸馏，能补的也只有「教师也不确定」的那一小块**，
而且要跨越 4 倍的尺度差。这与本项目已反复验证的结论一致：
**瓶颈不在估值精度/监督信号密度，而在「数据里有没有更优且可检测的动作」。**

**唯一值得做的不是蒸馏，而是诊断**：
用这 7,791 个点的 Q 差距分布，可以反推
「在一次训练规模下，能产生多少条真正有信息量的样本」。

## 4. 边界（不能从这份数据得到的结论）

1. **4.1c 到底比我们强多少，这份数据回答不了**。
   一致率衡量拟人度，与强度反向（4.1c 比 v3 更不像人却更强）。
2. **Q 的尺度不可直接比较**：4.1c 是名次 EV，我们是 MC 回报；比值 4.1 倍、
   排序相关 0.85 只能说明"价值观接近"，不说明"谁对"。
3. **样本只 12 局**（全部 202609），单局波动大；分层结论（rating/巡目）
   的组间差在 2~4pp，未做显著性检验，只能当趋势看。
4. **报告的 31 个点缺失**（碰/杠类）尚未查明原因，已排除，不影响主结论。

**踩过的坑（写进代码注释了）**

1. `tehai-state` 内嵌 `<ul class="consumed">` 展示副露，不先删掉会让手牌多 3 张，
   配对全错（14 vs 11）。
2. 局号要由 `(bakaze, kyoku)` 算，**不能用 `start_kyoku` 计数**——连庄不递增。
3. 报告的「跳过」类 entry 展示 **14 张手牌**（摸牌未打），本地是 13 张，所以
   **不能拿手牌做匹配键**，只能用（局号, 候选数）序列 + 手牌做后验校验。
4. `canon()` 必须同时认报告的小写牌名（`{n}`）和 mjai 的大写（`{N}`），
   否则我们自己的动作全被归一成 `discard:?`，打牌一致率错算成 54%。
5. 一致率**不能只比类别**：「打 X」和「打 Y」都是 discard，只比类别会把
   20% 的打牌分歧算成一致（首版因此算出 96.25%）。
