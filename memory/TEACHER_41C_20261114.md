# 从 48 份 4.1c 报告里再挖出的东西（2026-11-14）

> 一句话：**官方 4.1c 的报告不只给 argmax，每个决策点都带完整 Q 表**。
> 把 7,791 个决策点的 Q 全部抽出来、与我们 S6c 在同一批局面上逐点对齐后，
> 得到三个硬结论：① 之前报的「S6c 80.619% vs 4.1c 78.424%」是**跨点集比较**，
> 同点集应为 **80.349% vs 78.424%（+1.93pp）**；② 两个模型的 Q 排序相关 **ρ 中位 0.846**、
> 「把握」相关 **0.798**，**但 argmax 只在 86.4% 上一致**；
> ③ 4.1c 的「独有分歧」集中在**它自己也没把握**的地方（gap 中位 0.107），
> ⇒ **把它当教师蒸馏，能补的信息很少**。

## 0. 材料从哪来

上一轮人工提交产出 **48 份 HTML 报告**（12 局 × 4 席，全部 `model tag 4.1c`、
`τ=1.00`、半庄）。这些报告被当成"只读一致率"用掉了，但实际内容远不止：

```html
<details class="collapse entry" data-mark-red="">
  <summary>12巡 (余45)  2向听   #3/10</summary>       ← 巡目/余牌/向听/人类动作名次
  <ul class="tehai-state">…</ul>                       ← 手牌（含摸牌与副露）
  <span style="background:#ffd5d5"><span class="role">玩家: </span>打 {6p}</span>
  <span class="role">Mortal: </span>打 {5p}<details><table class="data">
    Action        Q̂^π(s,a)    π_τ(a|s)×100
    打 5p          0.24759      22.0423
    打 9m          0.13426      19.68061
    …（每个候选一行，5 位小数）
  </table></details>
</details>
```

⇒ **每个决策点都是一份完整的教师样本**：`(局面, 每个候选的 Q, 每个候选的 π)`，
不需要再提交任何一次请求。

**总量**：48 份 × 平均 162 点 = **7,791 个决策点**，每点 2~15 个候选（中位 10），
合计约 **8 万条 `(state, action, Q)`**。

### 0.1 顺手验证了 τ 的语义

采集时多存了一份同一牌谱、同一席位、**τ=0.1** 的重复报告（`a46f3cdd`）。
逐点比对：

| 检查 | 结果 |
|---|---|
| 牌谱 JSON 是否相同 | **完全相同** |
| Q 表是否相同 | **160/160 逐位相同** |
| π 的 top1 均值 | τ=0.1 → **88.56%**；τ=1.00 → **33.66%** |
| 一致率 | 两者都是 `124/161 = 77.019%` |

⇒ ① **Q 与 τ 无关**，τ 只作用在 π 上；② `π = softmax(Q/τ)`（实测偏差中位 0.00000）；
③ **argmax 与 τ 无关**，所以一致率不受温度影响。
附带意义：这与本仓库 `engine.py` 的 `boltzmann_temp` 语义**完全一致**（都是除以 $T$）。

## 1. 修正：同点集口径下差值是 +1.93pp，不是 +2.20pp

上一轮报的「S6c 80.619%」是**本地 `mask>=2` 的全量**，而「4.1c 78.424%」是
**reviewer 的 `reviewed` 集合**。两者分母恰好都是 7,791，但**点集不完全相同**：

| 口径 | 数量 | 说明 |
|---|---:|---|
| 本地 `FileDatasetsIter`（`mask>=2`） | **7,791** | 上一轮用的 |
| 报告 `total_reviewed` | **7,791** | 官方用的 |
| 我用 `PlayerState` 重放（`encode_obs(4,False)`） | **7,822** | 比前两者多 **31** 个 |

多出的 31 个点全部是**「碰 vs 跳过」「杠 vs 跳过」这类鸣牌决策**（13 张手牌、`mask={pass,pon}`），
reports 里没有对应 entry（visitor 侧被省略或统计口径不同）。
把它们排除、在**报告的 7,791 点上重算**，得到：

| 模型 | 分子/分母 | 一致率 |
|---|---:|---:|
| **官方 4.1c** | 6,110 / 7,791 | **78.424%** |
| **本仓库 S6c** | 6,260 / 7,791 | **80.349%** |
| 差 | +150 | **+1.925pp** |

⇒ **上轮的 +2.20pp 偏乐观 0.27pp**。方向上仍然「我们更像人」，但幅度要按 +1.93pp 说。

> 对齐质量：7791/7791 全部配到本地 obs；打牌点的手牌逐位一致率 **100%**
> （用（局号, 候选数）序列做 LCS，再做手牌校验）。局号口径要由 `(bakaze, kyoku)` 算，
> 不能用 `start_kyoku` 计数——**连庄不让局号递增**，否则整局错位。

## 2. 六条新发现

### 2.1 两个模型的「价值观」高度一致，但尺度差 4 倍

| 量 | 4.1c | S6c | 关系 |
|---|---:|---:|---|
| 打牌 Q 的 Spearman ρ（逐决策点） | — | — | 均值 **0.802**、中位 **0.846**、p10 0.595 / p90 0.951 |
| ρ > 0.5 的占比 | — | — | **94.21%**（ρ < 0 仅 0.24%） |
| `gap = top1−top2` 中位 | **0.399** | **1.627** | **4.1 倍** |
| gap 的 Pearson 相关 | — | — | **0.798** |
| 全候选跨度（max−min）中位 | **1.517** | — | p10 0.583 / p90 1.991 |
| top1 的 Q 中位 | **−0.071** | — | p10 −0.275 / p90 0.345 |

**读法**：Q 的**排序**几乎一样（ρ 0.85），但**幅度**差 4 倍。
做任何蒸馏/回归前必须先做仿射对齐，否则学到的全是尺度差。

### 2.2 argmax 只在 86.4% 上一致——差值全在「近似等价」的动作上

| 人类动作类型 | 点数 | 两模型 argmax 完全一致 |
|---|---:|---:|
| 打牌 | 5,990 | **83.96%** |
| 跳过/不鸣 | 1,292 | 96.21% |
| 碰 | 155 | 89.68% |
| 立直 | 117 | 85.47% |
| 吃 | 111 | 86.49% |
| 杠 | 13 | 84.62% |
| 和/自摸 | 112 | 100% |
| **合计** | **7,791** | **86.40%** |

**结合 2.1**：ρ=0.85 但 argmax 只 84% ⇒ 分歧的那些点，两边的 top1「价值」几乎相等。
这不是「打错了」，是**在平坦区域里选了点**。

### 2.3 4.1c 分歧的地方，有 2/3 我们也分歧（「AI 共识」）

| 拆分 | 点数 | 占 4.1c 分歧 |
|---|---:|---:|
| 4.1c 分歧总计 | 1,681 | 100% |
| ├─ **S6c 与人类一致**（4.1c 孤立） | 527 | 31.35% |
| └─ **S6c 也与人类分歧**（AI 共识） | **1,154** | **68.65%** |

反向：S6c 分歧 1,531 点中，4.1c 与人类一致的只有 377（24.6%）。

而两组的**把握**截然不同：

| 组 | 4.1c gap 中位 | 人类动作类型（前二） |
|---|---:|---|
| 4.1c 孤立（n=527） | **0.107**（几乎纯随机） | 打牌 88.0% / 跳过 8.3% |
| AI 共识（n=1,154） | **0.213** | 打牌 93.6% / 吃 2.5% |

⇒ **4.1c 最「有主见」的地方，我们和它站在一起；它孤立的地方，它自己也没把握。**

「AI 共识」组里，两个 AI 选**同一张牌**的比例只有 **58.9%** ——
即"都反对人类"但方式不同，说明这是**一片平坦区域**，不是同一个明确答案。

### 2.4 两个模型对「这手难不难」的判断完全同步

按 4.1c 的 gap 四分位分桶：

| 4.1c gap | 点数 | 4.1c 分歧率 | S6c 一致率 | **S6c 的 gap 中位** |
|---|---:|---:|---:|---:|
| [0.000, 0.163) | 1,497 | **50.50%** | **57.78%** | **0.664** |
| [0.164, 0.401) | 1,497 | 33.47% | 68.27% | 1.068 |
| [0.401, 0.828) | 1,497 | 16.23% | 82.97% | 2.034 |
| [0.829, 1.915) | 1,498 | **2.87%** | **96.20%** | **4.606** |

**两列同时单调、且几乎同步**：4.1c 越确定，S6c 也越确定、越像人。
⇒ 两个模型（不同代次、不同训练目标、不同 Q 尺度）对**局面难度的排序几乎一致**。
这是"这批数据本身有难易结构"的直接证据，不是某个模型的偏差。

### 2.5 高段位玩家的动作更容易被预测

按玩家天凤 rating 四分位（rating 来自报告内嵌的 `tenhou.net/6` JSON，是新拿到的信息）：

| rating 区间 | n | 4.1c 一致率 | S6c 一致率 |
|---|---:|---:|---:|
| [2051, 2107) | 1,947 | 77.20% | 79.51% |
| [2107, 2160) | 1,947 | 77.71% | 79.51% |
| [2160, 2215) | 1,947 | 77.61% | 80.64% |
| **[2215, 2298]** | 1,950 | **81.18%** | **81.74%** |

⇒ 最高四分位的一致率比最低高 **4.0pp（4.1c）/ 2.2pp（S6c）**。
**「像人」这件事本身有水平梯度**：打得越好越可预测（不是越"正确"，是越"少随手"）。

按巡目分层也一致：早巡（0-5）一致率 76.0%/79.8%，中巡（10-15）81.8%/82.4%。
**早巡更难预测**（选择空间大、信息少）。

### 2.6 分歧的形态：90% 是「人类打这张，它打那张」

| 人类动作 | 4.1c 选择 | 次数 |
|---|---|---:|
| 打牌 | 打**另一张** | **1,518** |
| 跳过 | 碰 | 34 |
| 吃 | 跳过 | 34 |
| 跳过 | 吃 | 32 |
| 打牌 | **立直** | 23 |
| 立直 | 打牌（不立直） | 18 |
| 碰 | 跳过 | 13 |
| 杠 | 打牌 | 4 |
| 打牌 | 杠 | 3 |

⇒ 分歧几乎全是打牌，且**不是"该不该副露"层面的分歧**（那类只占 ~8%）。
这对"4.1c 是争一型、打法更激进"的假说是**弱支持**：
立直相关只有 41 例（23 立直 + 18 不立直），量太小，无法据此判定风格差异。

## 3. 对「能不能蒸馏 4.1c」的判断：价值比想象低

把上面几条拼起来：

| 前提 | 数据 |
|---|---|
| 教师与学生的 Q 排序相关 | **0.846**（已高度重合） |
| argmax 分歧 | 13.6%（1,060 点） |
| 分歧中「学生也反对人类」 | **68.65%** ⇒ 这些点学生**本来就这么想**，蒸馏不改变策略 |
| 分歧中「教师独有」 | 31.35%（527 点），**其 gap 中位仅 0.107** ⇒ 教师自己也没把握 |
| 可用样本量 | 7,791 点 ≈ 一次训练看到的 **0.008%**（9,200 万） |

⇒ **即使把 Q 全部拿来蒸馏，能补的也只有「教师也不确定」的那一小块**，
而且要跨越 4 倍的尺度差。这与本项目已反复验证的结论一致：
**瓶颈不在估值精度/监督信号密度，而在「数据里有没有更优且可检测的动作」。**

**唯一值得做的不是蒸馏，而是诊断**：
用这 7,791 个点的 Q 差距分布，可以反推
「在一次训练规模下，能产生多少条真正有信息量的样本」。

## 4. 边界（不能从这份数据得到的结论）

1. **4.1c 到底比我们强多少，这份数据回答不了**。
   一致率衡量拟人度，与强度反向（4.1c 比 v3 更不像人却更强）。
2. **Q 的尺度不可直接比较**：4.1c 是名次 EV，我们是 MC 回报；比值 4.1 倍、
   排序相关 0.85 只能说明"价值观接近"，不说明"谁对"。
3. **样本只 12 局**（全部 202609），单局波动大；分层结论（rating/巡目）
   的组间差在 2~4pp，未做显著性检验，只能当趋势看。
4. **报告的 31 个点缺失**（碰/杠类）尚未查明原因，已排除，不影响主结论。

```bash
    -o logs/teacher41c/teacher_41c.jsonl --summary logs/teacher41c/SUMMARY.md
# 2) 对齐 + 前向（需要 libriichi + GPU）
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0 MORTAL_CFG=config.s6c.toml \
    python align_teacher41c.py
```

**踩过的坑（写进代码注释了）**

1. `tehai-state` 内嵌 `<ul class="consumed">` 展示副露，不先删掉会让手牌多 3 张，
   配对全错（14 vs 11）。
2. 局号要由 `(bakaze, kyoku)` 算，**不能用 `start_kyoku` 计数**——连庄不递增。
3. 报告的「跳过」类 entry 展示 **14 张手牌**（摸牌未打），本地是 13 张，所以
   **不能拿手牌做匹配键**，只能用（局号, 候选数）序列 + 手牌做后验校验。
4. `canon()` 必须同时认报告的小写牌名（`{n}`）和 mjai 的大写（`{N}`），
   否则我们自己的动作全被归一成 `discard:?`，打牌一致率错算成 54%。
5. 一致率**不能只比类别**：「打 X」和「打 Y」都是 discard，只比类别会把
   20% 的打牌分歧算成一致（首版因此算出 96.25%）。
