## 1. P0 严重（3 条，建议 A2c 验收前处理）

### S1｜A3 规则基线被定性为「顺序盲地板」，但代码实际消费时序 token（类别 B）

- 证据：`rule_baseline.py:203` `early_discard_mask(tl_tokens, tl_mask)`（取每家**前 3 次舍牌**，
  顺序相关）；`:305` `timeline_features(...)`（摸切/手切、末动作、巡目、舍牌数）；
  `:626`/`:631` 二者**确实进入打分**（`rule_alloc_probs(early_river=...)`、
  `rule_tenpai_prob(feat, ...)`，其中 `:369-375` 用 `feat['tg_tail']`/`all_simples`/
  `honor_types_discarded`/`n_disc` 参与 logit）。
- 冲突方：`order_metrics.py:10` 与 README §12 把 A3 的格内 ΔΔ 称作「**顺序盲地板**」，
  并据此定义 RM13/RM14 判据（「net 超出地板 ≥90% / ≥+30%」）；README §12.4 的论证是
  「每格两组舍牌**集合**完全相同 ⇒ 顺序盲预测器的格内 ΔΔ 只来自组成差异」。
- 影响：A3 **不是**顺序盲预测器。格内两组虽然舍牌集合相同，但**顺序不同**，而 A3 的
  早巡舍牌掩码/时序特征会随顺序改变 ⇒ 其 ΔΔ（实测 floor=0.0299）中可能含**真实的顺序响应**，
  不是纯组成混杂。因此「net 超地板」的比例被系统性低估，且「地板」这个上界解释不成立。
  （注：`early_discard_mask` 仅在 a_/c_ 之一落入前 3 次舍牌时才产生组间差异，
  故实际污染量级未知——这正是需要量化的原因。）
- 处置：① 术语改为「**规则法地板**」或「启发式参照」，不再宣称顺序盲；
  ② 若要保留「组成混杂地板」的解释，需构造**真顺序盲变体**（把 `tl_tokens` 的 token 顺序
  规范化/打乱后再喂 A3，或直接令 `early_river=None`、`feat` 取常数），用它作 RM13/RM14 的地板；
  ③ 在 `order_metrics.py` 输出里同时给「A3 原样」与「A3 顺序盲化」两条地板，差值即 A3 自身的顺序敏感度。

### S2｜门禁无「期望项数」断言，早退 `return` 会静默缩减覆盖（类别 D）

- 证据：`test_pipeline.py` 中 `:457`/`:462`/`:595`/`:893`/`:901` 共 5 处 `return`——subprocess
  失败即返回，**该层后续 check 全部不执行、也不记 FAIL**；`:946` 摘要仅在 `FAILS` 非空时非零退出；
  `check()` 无「期望总数」概念。另 `:841` `check('I4 A2b ckpt 不在仓库（跳过兼容断言）', True)`
  ——**把 SKIP 记成 PASS**。
- 影响：这是坑 57「连续三次假 PASS」得以存活的**结构性原因**：只要不出现显式 FAIL，
  覆盖缩水到 60 项也照样打印 `ALL PASS`。本轮修复后是 71 项，但**没有任何机制**能在
  下次缩水时报警。
- 处置：① `main()` 增加 `--expect N`（默认写死当前项数），实到项数 ≠ N 即 FAIL；
  ② 新增 `skip()` 与 `check()` 分离，SKIP 不计入通过数并在摘要单列；
  ③ 早退处改为「记 FAIL 后继续下一层」而非 `return`（或至少在摘要打印被跳过的层）。

### S3｜README §12.4 单格 ΔΔ 的减数顺序与表头相反；坑 55 术语与其自身规则矛盾（类别 A）

- 证据：§12.4 表头约定 ΔΔ = **非自然 − 自然**（`order_metrics.py` 与
  `diagnostics/s3158_local_strata.py` 的 `sgn`/`NAT` 实现完全一致，已逐位复核：
  `truth_dd=0.07986082020685903`、floor、bootstrap 数组全等）；但同节单格句写
  「索 m=8：真值 ΔΔ(**先9s后7s** − **先7s后9s**) = −0.2956」——对 m=8 而言「先9s后7s」
  恰是**自然**序（`NAT[8]='desc'`），故该句是 **自然 − 非自然**，与表头相反。
  坑 55 又写「m∈{2,3,4} 自然是**内侧先**」，而它自己的定义是「`d(x)=min(x−1,9−x)` 更小者先切」
  ＝靠边/外侧先；代码 `NAT={2:'asc',3:'asc',4:'asc',...}` 中 `asc` = 先切 a_（1m/2m/3m 里的 1m，
  d=0，**靠边**）⇒ **代码正确、术语错误**。
- 影响：同一符号 ΔΔ 在同一节内两种顺序，且 per-cell 数值**未存档**
  （`diagnostics/results/local_order_report2.json` 只有聚合值 + bootstrap），
  事后无法裁决 −0.2956 属于哪种约定。这条是 P1b（顺序通路专项）的**领域知识依据**，
  符号读反会直接导致改错方向。
- 处置：① §12.4 单格句统一改写为表头约定（并显式标注自然/非自然）；
  ② 坑 55 的「内侧先」改为「靠边先（d 更小）」；
  ③ `order_metrics.py` 增加 per-cell 明细落盘（`single_tile.cells`），使任何单格数字可复核。

| 「`s315_*` 诊断脚本未透传 `wait_head`，加载 A2c(tile) ckpt 会出错」 | **否决** | `s315_wait_calib.py:25`、`s315_arch_audit.py:30`、`s315_strat_auc.py:25`、`s315_head_probe.py:46`、`diagnostics/_common.py:65` **全部**为 `wait_head=cfg.get('wait_head','flat')`（多行调用被单行 grep 截断造成的误判）。同理 `evaluate.py:155/160`、`compare_a3.py:136/140`、`compare_v1_v2.py:52/57` 也已透传 ⇒ **A2c 验收链不会因架构参数断裂**（`load_state_dict` 严格模式，形状不符会**响亮失败**而非静默） |
| 「`build_fixed_eval_set` 调用处不传 seed，违反 seed 纪律」 | **部分否决** | 函数签名默认 `seed=20261016`，调用方不传即固定 ⇒ 当前**可复现**；真实缺陷是「不可覆盖 + 产物不记录 seed」→ M8 |
| 「`order_metrics.py` 的 sidecar 由 `s3158_local_extract.py` 写入」 | **否决** | `cache.meta.json` 由 `order_metrics.py:85-95` 自身写入并校验 ckpt 身份 |
| 「`tenpai_mask` 含振听会让 CE34 严重失真」 | **量化后降级** | `furiten_frac = 0.125%` ⇒ 数值可忽略，仅口径表述问题 → M2 |
