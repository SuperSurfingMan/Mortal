# 立直前后打牌信息的利用方式（A2c 消融探针，2026-11-03）

## 问题

立直后立直家只能摸切，打出的牌除「不和这张牌」外几乎无信息；立直前的手切则
携带选牌/留牌信息。两者应被区别对待。模型是否捕捉到了这一点？

## 一、代码事实（先看特征层能不能区分）

| 项 | 状态 |
|---|---|
| `post_riichi_river` | **死参数**：在 `constraints.compute_wait_bias` 签名里，但函数体只引用 `unseen`/`river`，docstring 标「诊断用」 |
| `tl_tokens`（43 维） | 牌 one-hot(34) + **摸切(1)** + 动作(7) + 巡目(1)，**没有「立直后」标志** |
| `post_riichi` 字段 | 只作为侧车 `flags[...,0]` 传给 **tile 模式**；A2c 是 `pooled`，**不吃侧车** |

⇒ A2c 只能靠「reach token 之后全是 tsumogiri」间接推断，没有任何显式信号。

## 二、消融结果（A2c / 40000 样本 / riichi 层 n=8504）

| 变体 | alloc_ce | Δ | wait_ce | Δ |
|---|---:|---:|---:|---:|
| `base` | 0.6018 | — | 2.8544 | — |
| `zero_tg`（抹掉摸切标志） | 0.6054 | +0.0035 | 2.8683 | +0.0139 |
| `drop_post`（删立直后 token） | 0.6023 | **+0.0005** | 2.8591 | **+0.0047** |
| `drop_pre`（删立直前 token） | 0.6837 | **+0.0819** | 4.1019 | **+1.2475** |
| `drop_all`（全删） | 0.6112 | +0.0094 | — | — |

**敏感度比 `R = Δpost / Δpre`：**

- `alloc_ce`：**0.006**（0.6%）
- `wait_ce`：**0.004**（0.4%）

**判定：CAPTURED。** 模型几乎完全忽略立直后的动作（CE 只动 0.0005），
而严重依赖立直前的动作（CE 恶化 0.0819，160 倍）。你描述的机制模型确实学到了，
而且是隐式学到的（没有任何显式标志）。

旁证：`zero_tg` 只让 CE 变差 0.0035 —— 连「摸切标志」本身都几乎没被用。
一旦模型知道「立直后的 token 不重要」，就不需要靠摸切标志去筛。

## 三、但这不解释立直层盲区

立直层扣地板复现率 66.2%、区域级 excess −0.0656，缺口不在「怎么处理立直后的牌」：

1. **立直后的牌已由 `river` 硬掩码处理**（`hard_river_mask` 把所有打出的牌置 −inf）
   ⇒「不和这张牌」这个信息在约束层就吃掉了，`tl_tokens` 里那部分本来就冗余。
2. **立直前的信息量本身不够**：立直通常发生在 6~10 巡，此前只有几次舍牌；
   立直把「听牌」这个强约束加上后，剩余不确定性全在「听的是什么」——从未被观察到。
3. **听牌组合空间太大**：27 类形状在立直 `active_both` 上 p_max 0.6547，
   有效类只有 3.4。

⇒ **加显式「立直后」标志无收益**（本实验已证伪）；立直层的出路是换任务定义
（27 类形状 → 待牌命中），因为 `wait` 标签在立直层最均衡（最大正例率 0.117）。

## 四、方法论陷阱：`drop_all` < `drop_pre`

`drop_all`（+0.0094）的影响**小于** `drop_pre`（+0.0819）。直觉上「全删」应 ≥
「删一部分」，结果相反。

原因是 **OOD**：全 mask 后 attention pooling 输出全零嵌入，而模型在训练中见过这种
输入（开局快照，无 token）；但「只有立直后 token、没有立直前」是训练中几乎不存在的
分布，模型没有应对策略，CE 因此暴涨。

**消融实验必须看比值（R=0.006），不能看绝对量。**

## 五、结论

| 问题 | 答案 |
|---|---|
| 模型是否区分立直前后？ | **是**（R=0.006 / 0.004） |
| 是靠显式标志吗？ | 否，靠 reach token + attention pooling 隐式推断 |
| 需要补「立直后」标志吗？ | **不需要**，模型已经不用那部分信息 |
| 这是立直层盲区的原因吗？ | **不是**，缺口在立直前信息量与任务定义 |
